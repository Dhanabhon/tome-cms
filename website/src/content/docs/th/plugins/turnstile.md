Cloudflare Turnstile ใส่ challenge ของ Cloudflare ไว้ในฟอร์มรหัสกู้คืนที่ `/recovery` ทุกครั้งที่มีคนกรอกรหัสกู้คืน เซิร์ฟเวอร์จะถาม Cloudflare ก่อนแล้วจึงอ่านรหัส ถ้าไม่ผ่าน challenge ก็จะไปต่อไม่ได้ รหัสกู้คืนเป็นความลับอย่างเดียวที่คุณต้องพิมพ์เอง จึงเป็นที่เดียวที่มีคนเดาได้ การเข้าสู่ระบบด้วย passkey ไม่เจอ challenge เพราะ passkey เดาไม่ได้ การสร้าง passkey ตอนท้ายของการกู้คืนก็ไม่เจอเช่นกัน และผู้อ่านไม่เคยเจอ

ก่อน 1.17.0 challenge อยู่ที่ฟอร์มเข้าสู่ระบบ ที่ย้ายมาเพราะมันเคยปฏิเสธ passkey ที่ใช้ได้จริง

## หน้าปลั๊กอิน

หน้า "ปลั๊กอิน" ใต้ "หน้าตาเว็บไซต์" ในกลุ่ม "การตั้งค่า" มีการ์ดของปลั๊กอินทุกตัวที่มากับ TomeCMS ทุกตัวปิดอยู่จนกว่าคุณจะเปิดเอง

![หน้า "ปลั๊กอิน" มีการ์ดหกใบ คือ "Cloudflare Turnstile" "Sticky Banner" "Popup" "Image lightbox" "Jev (TypeSafe AI)" และ "MCP" ซึ่งมีป้าย "ทางการ" แต่ละใบมีชื่อปลั๊กอินและคำอธิบายว่าทำอะไร ถัดลงมาเป็นแถบบอกว่าปลั๊กอินทำงานตรงไหน เช่น "ฟอร์มรหัสกู้คืน" บนการ์ด Turnstile หรือ "ทุกหน้าสาธารณะ" แล้วจึงเป็นสวิตช์กับปุ่ม "ตั้งค่า" การ์ด Turnstile, Popup และ Jev ขึ้นว่า "ยังไม่ได้ตั้งค่า" ส่วน Sticky Banner, Image lightbox และ MCP ขึ้นว่า "ปิด" ใต้การ์ดทั้งหมดคือ "ปลั๊กอินมาจากไหน" และ "ปลั๊กอินล็อกคุณออกจากระบบไม่ได้"](../../../../assets/screenshots/th/plugins.png)

แถบบนการ์ดแต่ละใบบอกว่าปลั๊กอินทำงานตรงไหน คือ "ฟอร์มรหัสกู้คืน" "ทุกหน้าสาธารณะ" "คำแนะนำระหว่างเขียน" หรือ "แอป AI ผ่าน MCP" เมื่อกดสวิตช์ท้ายการ์ด ระบบจะถามก่อน และบอกว่าปลั๊กอินจะเริ่มหรือหยุดทำอะไร กด "เปิดใช้งาน" หรือ "ปิดใช้งาน" จึงจะมีผล ส่วน "ยกเลิก" จะปล่อยปลั๊กอินไว้ตามเดิม คำข้างสวิตช์บอกสถานะ คือ "เปิด" "ปิด" หรือ "ยังไม่ได้ตั้งค่า" ถ้ายังมีการตั้งค่าที่ปลั๊กอินต้องใช้แต่ยังว่างอยู่ ปลั๊กอินที่ยังไม่ได้ตั้งค่าจะเปิดใช้ไม่ได้

ปุ่ม "ตั้งค่า" เปิดแผงการตั้งค่าของปลั๊กอินขึ้นมาทางข้างจอ ชื่อแผงคือ "ตั้งค่า" ตามด้วยชื่อปลั๊กอิน ระหว่างที่ยังขาดข้อมูลที่ต้องใช้ ด้านบนของแผงจะขึ้นว่า "กรอกข้อมูลที่จำเป็นให้ครบก่อนเปิดใช้งาน" กด "บันทึก" แล้วการ์ดจะขึ้นว่า "บันทึกแล้ว" การบันทึกไม่เปลี่ยนสถานะเปิดหรือปิดของปลั๊กอิน

การตั้งค่าบางช่องเป็นค่าลับ เช่น key ของบริการอื่น ค่าลับถูกเข้ารหัสด้วย `TOME_CMS_CONTEXT_SECRET` ก่อนเก็บ และไม่เคยถูกส่งกลับมาที่เบราว์เซอร์ ช่องนี้จึงว่างอยู่เสมอ และเมื่อเก็บค่าไว้แล้วจะขึ้นว่า "เก็บไว้แล้ว เว้นว่างไว้เพื่อใช้ค่าเดิม" ถ้าเว้นว่างไว้ ค่าที่เก็บไว้จะยังอยู่ ถ้าพิมพ์ค่าใหม่ ค่าเดิมจะถูกแทนที่ หน้า[การตั้งค่า](/tome-cms/th/running/configuration/)อธิบายว่าทำไมห้ามเปลี่ยนค่านี้หลังติดตั้งเว็บแล้ว

ปลั๊กอินมาพร้อมกับ TomeCMS ตามที่การ์ด "ปลั๊กอินมาจากไหน" บอกไว้ หน้านี้ไม่มีทางติดตั้งปลั๊กอินเพิ่ม การ์ด "ปลั๊กอินล็อกคุณออกจากระบบไม่ได้" บอกเหตุผลไว้ว่า ปลั๊กอินไม่เคยขวาง passkey ของคุณ หรือ passkey ที่สร้างตอนกู้คืนบัญชี และคำตอบที่ถามไม่ได้ก็ไม่นับเป็นการปฏิเสธ ปลั๊กอินทุกตัวยังสั่งปิดจากเซิร์ฟเวอร์ได้ด้วย `npm run plugin:disable` ตามด้วย id ของปลั๊กอิน คือ `turnstile`, `typesafe` ของ Jev, `notice` ของ Sticky Banner, `popup` และ `lightbox`

## ตั้งค่า Turnstile

1. ใน dashboard ของ Cloudflare ให้เพิ่ม widget ของ Turnstile สำหรับชื่อโฮสต์ของเว็บคุณ ซึ่งก็คือชื่อใน `TOME_CMS_PUBLIC_URL` แล้ว Cloudflare จะให้ site key กับ secret key มา
2. บนการ์ด "Cloudflare Turnstile" กด "ตั้งค่า" วาง key ทั้งสองลงไป แล้วกด "บันทึก"
3. เปิดสวิตช์ การ์ดจะขึ้นว่า "เปิด"

| การตั้งค่า | ในหน้าภาษาอังกฤษ | ใช้ทำอะไร |
| --- | --- | --- |
| "Site key" | "Site key" | key ที่ทำให้ challenge แสดงในฟอร์มรหัสกู้คืน เป็นข้อมูลสาธารณะ และถูกส่งไปถึงเบราว์เซอร์ของคุณพร้อมกับฟอร์ม ต้องกรอก |
| "Secret key" | "Secret key" | key ที่เซิร์ฟเวอร์ใช้ถาม Cloudflare ว่าผ่าน challenge หรือไม่ เก็บแบบเข้ารหัสและจะไม่แสดงอีก ต้องกรอก |

challenge จะขึ้นก็ต่อเมื่อเก็บ key ไว้ครบทั้งสองตัวแล้ว

## กู้คืนบัญชีเมื่อเปิดปลั๊กอินไว้

ฟอร์มรหัสกู้คืนจะมี challenge อยู่เหนือช่อง "รหัสกู้คืน" รอให้ challenge เสร็จก่อนกด "ดำเนินการต่ออย่างปลอดภัย" ถ้ากดก่อน ฟอร์มจะขึ้นว่า "รอให้การตรวจสอบเสร็จก่อน ถ้าตัวตรวจสอบไม่ขึ้นเลย ให้รันคำสั่ง npm run plugin:disable turnstile บนเซิร์ฟเวอร์" และไม่ส่งอะไรออกไป เมื่อกดแล้ว เซิร์ฟเวอร์จะส่งคำตอบของ challenge ไปให้ Cloudflare ก่อน แล้วรอคำตอบไม่เกินห้าวินาที

| Cloudflare ตอบว่า | ผลที่ตามมา |
| --- | --- |
| ผ่าน challenge | เซิร์ฟเวอร์ตรวจรหัสกู้คืนต่อตามปกติ |
| คำตอบผิด ถูกใช้ไปแล้ว หรือไม่มีคำตอบเพราะ challenge ไม่ขึ้นเลย | ถูกปฏิเสธโดยไม่อ่านรหัส และฟอร์มขึ้นว่า "ไม่ผ่านการตรวจสอบก่อนกู้คืนบัญชี" พร้อมบอกให้ลองอีกครั้ง หรือปิดปลั๊กอินจากเซิร์ฟเวอร์ เซิร์ฟเวอร์บันทึกเหตุผลจาก Cloudflare ลง log |
| ไม่ได้คำตอบที่ใช้ได้ เช่น secret key ผิด Cloudflare ตอบกลับเป็นข้อผิดพลาด ติดต่อไม่ได้ หรือไม่ตอบภายในห้าวินาที | เซิร์ฟเวอร์บันทึกสาเหตุลง log แล้วตรวจรหัสกู้คืนต่อ |

คำตอบแต่ละครั้งใช้ตรวจได้ครั้งเดียว ถ้ากดแล้วเริ่มการกู้คืนไม่สำเร็จ ฟอร์มจะขอคำตอบใหม่จาก challenge ทุกครั้ง การลองอีกครั้งจึงไม่ส่งคำตอบที่ใช้ไปแล้วซ้ำ

แถวสุดท้ายนี้เองที่ทำให้ secret key ที่พิมพ์ผิดไม่ล็อกคุณออกจากเว็บของตัวเอง ถ้า challenge ไม่ขึ้นในเบราว์เซอร์ของคุณ ให้ปิดปลั๊กอินจากเซิร์ฟเวอร์ หรือสร้างลิงก์กู้คืนแบบใช้ครั้งเดียวที่นั่นด้วย `npm run admin:recover` ซึ่งไม่ต้องผ่านฟอร์มนี้ หน้า[กลับเข้าหน้าผู้ดูแล](/tome-cms/th/running/recovery/)มีทั้งสองวิธี

เมื่อคุณเข้าสู่ระบบอยู่แล้วและแอดมินขอ passkey อีกครั้ง เพื่อติดตั้งอัปเดตหรือสร้างรหัสกู้คืนชุดใหม่ จะไม่แสดงและไม่ตรวจ challenge ใน 1.1.0 และก่อนหน้าจะตรวจ และสองอย่างนั้นก็ใช้ไม่ได้ ดู[แก้ปัญหา](/tome-cms/th/running/troubleshooting/#ยืนยันด้วย-passkey-ไม่สำเร็จ-อาจถูกยกเลิกไป-ลองอีกครั้ง-ตอนติดตั้งอัปเดต)

## ข้อมูลที่ส่งไปถึง Cloudflare

ในเบราว์เซอร์ของคุณ หน้ากู้คืนที่ `/recovery` จะโหลดสคริปต์ของ Cloudflare จาก `challenges.cloudflare.com` และ challenge ทำงานอยู่ในหน้านั้น Cloudflare จึงเห็นสิ่งเดียวกับที่เว็บไหนก็เห็นเมื่อเบราว์เซอร์ไปโหลดไฟล์จากเว็บนั้น รวมถึง address ของคุณ หน้าอื่นไม่โหลดสคริปต์นี้ และผู้อ่านหน้าเว็บสาธารณะไม่มีทางไปถึง Cloudflare ผ่านปลั๊กอินนี้

จากฝั่งเซิร์ฟเวอร์ การกรอกรหัสกู้คืนแต่ละครั้งจะส่ง secret key คำตอบที่ challenge ให้เบราว์เซอร์ของคุณไว้ และ address ที่คำขอนั้นมาจาก ไปที่ `siteverify` ของ Cloudflare ไม่มีข้อมูลเนื้อหาหรือผู้อ่านของคุณถูกส่งไปเลย หน้า[สิ่งที่เบราว์เซอร์ของผู้อ่านเก็บไว้](/tome-cms/th/running/privacy/)รวบรวมบริการทั้งหมดที่เว็บติดต่อได้ไว้
