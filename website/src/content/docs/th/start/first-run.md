เมื่อสคริปต์ deploy ทำงานเสร็จ ให้เปิด `/install` บน origin ของ CMS เช่น `https://cms.example.com/install` ตัวช่วยตั้งค่ามีหกขั้นตอน และไม่ถามรหัสผ่านเลยสักขั้น

หน้านี้เปิดมาเป็นภาษาไทยอยู่แล้ว ถ้าต้องการภาษาอังกฤษ เลือกได้จากเมนูภาษาด้านบน หรือเปิด `/install?lang=en`

ต้องเปิดจากที่อยู่เดียวกับ `TOME_CMS_PUBLIC_URL` ทุกตัวอักษร และต้องเป็น HTTPS เพราะ Passkey ที่สร้างในตอนท้ายจะผูกกับชื่อโฮสต์นั้น ถ้าเปิดจากที่อยู่อื่น ตัวช่วยจะไม่ให้ไปต่อ

## ขั้นที่ 1: ตรวจสอบระบบ

ตัวช่วยตรวจสี่อย่าง และทั้งสี่ต้องขึ้นว่า "พร้อม" ก่อนจึงจะไปต่อได้

| รายการ | สิ่งที่ตรวจ |
| --- | --- |
| "PostgreSQL database" | ฐานข้อมูลตอบสนอง |
| "Database migrations" | ไม่มี migration ค้างอยู่ |
| "S3-compatible storage" | bucket ตอบสนองที่ `S3_ENDPOINT` |
| "HTTPS / Passkey identity" | `TOME_CMS_PUBLIC_URL` เป็น HTTPS บนชื่อโฮสต์ที่ไม่ใช่ IP และตรงกับที่อยู่ที่เปิดอยู่ |

รายการไหนไม่ผ่านจะขึ้นว่า "ต้องแก้ไข" พร้อมคำแนะนำ แก้ตามนั้นแล้วกด "ตรวจอีกครั้ง" สำหรับการติดตั้งบน VPS ในตอนนี้ ถ้ามี migration ค้างหรือคอนเทนเนอร์หยุดทำงาน ให้รัน `./scripts/deploy-vps.sh` อีกครั้ง ส่วนถ้าเปิดตัวช่วยจากที่อยู่อื่น คำแนะนำจะบอกที่อยู่ที่ถูกต้องให้

เมื่อผ่านครบทั้งสี่ กด "ตั้งชื่อเว็บไซต์" เพื่อไปขั้นถัดไป

## ขั้นที่ 2: ข้อมูลเว็บไซต์

| ช่อง | สิ่งที่ต้องกรอก |
| --- | --- |
| "ชื่อเว็บไซต์" | ชื่อที่ผู้อ่านเห็น ต้องกรอก ยาวได้ไม่เกิน 120 ตัวอักษร |
| "Tagline" | ประโยคสั้น ๆ ใต้ชื่อเว็บ ไม่เกิน 120 ตัวอักษร |
| "คำอธิบายเว็บไซต์" | คำอธิบายสำหรับหน้าแรกและเครื่องมือค้นหา ไม่เกิน 160 ตัวอักษร |
| "ภาษาเริ่มต้น" | ไทย หรือ English ค่าตั้งต้นคือภาษาที่ตัวช่วยแสดงอยู่ และหน้าแอดมินจะใช้ภาษานี้ด้วย |
| "เขตเวลา" | `Asia/Bangkok` หรือ `UTC` วันที่บนหน้าเว็บและในหน้าแอดมินจะแสดงตามเขตเวลานี้ |
| "URL สำหรับ Admin" | ที่อยู่ของหน้าแอดมิน ต้องกรอก |

ทุกช่องยกเว้นที่อยู่แอดมินแก้ภายหลังได้ที่เมนู "ตั้งค่า" แล้วเลือก "ทั่วไป"

### ที่อยู่แอดมิน

ช่องนี้มีค่าตั้งต้นเป็น `/admin` จะเปลี่ยนเป็นอย่างอื่นก็ได้ เช่น `/studio` รูปแบบคือเครื่องหมาย `/` ตามด้วยตัวพิมพ์เล็ก ตัวเลข หรือขีดกลาง รวม 2 ถึง 40 ตัว และตัวแรกต้องเป็นตัวอักษรหรือตัวเลข path ที่ระบบใช้อยู่แล้วเลือกไม่ได้ ได้แก่ `/api`, `/install`, `/health`, `/_astro`, `/blog`, `/th`, `/en` และ `/recovery`

ติดตั้งเสร็จเมื่อไร ให้บุ๊กมาร์กที่อยู่นี้ไว้ทันที หน้าเว็บสาธารณะไม่มีลิงก์ไปหน้าแอดมิน และถ้าเลือก path อื่นที่ไม่ใช่ `/admin` ที่อยู่ `/admin` จะตอบ `404` อีกทั้งในหน้าแอดมินก็ไม่มีที่ให้เปลี่ยน path นี้ภายหลัง ต่อไปคุณจะเข้าสู่ระบบผ่านที่อยู่นี้ เช่น `https://cms.example.com/studio`

## ขั้นที่ 3: ข้อมูลเจ้าของ

"อีเมลเจ้าของ" ใช้เป็นชื่อบัญชีของเจ้าของเว็บ กรอกให้ครบทั้งที่อยู่ ขั้นนี้ไม่มีการตั้งรหัสผ่าน เพราะการเข้าสู่ระบบใช้ Passkey ที่อุปกรณ์ของคุณเก็บไว้

## ขั้นที่ 4: Installation token

token นี้ยืนยันว่าคุณเป็นคนควบคุมเซิร์ฟเวอร์ที่กำลังติดตั้ง สคริปต์ deploy พิมพ์ token ไว้ตอนท้าย และยังเก็บอยู่ใน `.env.local` ในโฟลเดอร์โค้ด

```sh
grep '^TOME_CMS_INSTALL_TOKEN=' .env.local
```

ค่าจะอยู่ในเครื่องหมายคำพูดเดี่ยว ให้วางเฉพาะตัวค่าลงในช่อง "Installation token" แล้วกด "ตรวจ token" เซิร์ฟเวอร์จะตรวจค่านี้ และตัวช่วยไม่เก็บ token ไว้

กล่อง "Installation token อยู่ที่ไหน?" ในตัวช่วยมีคำสั่งให้สองแบบ สำหรับการติดตั้งในตอนนี้ ให้ใช้คำสั่งของ "Local" แม้จะติดตั้งบน VPS ก็ตาม เพราะสคริปต์เขียน token ไว้ใน `.env.local` ส่วนคำสั่งของ "VPS" อ่านจาก `/etc/tome-cms/tome-cms.env` ซึ่งมีเฉพาะการติดตั้งแบบ managed ตั้งแต่ 1.0.0

ถ้า token ผิด ตัวช่วยจะแจ้งว่า "Token หรือ Passkey session ไม่ถูกต้อง กรุณายืนยันใหม่" ลองได้แปดครั้งภายใน 15 นาทีต่อหนึ่ง IP หลังจากนั้นต้องรอสักพัก เมื่อ token ผ่านแล้ว คุณมีเวลา 10 นาทีทำขั้นถัดไปให้เสร็จ ถ้าเกินเวลาต้องตรวจ token ใหม่

## ขั้นที่ 5: Passkey หลัก

ตัวช่วยจะสรุปสิ่งที่กำลังจะตั้งค่าให้ดู คือ "เว็บไซต์" "เจ้าของ" "Passkey RP" (TomeCMS และชื่อโฮสต์ของคุณ) และ "Admin URL" จากนั้นกด "สร้าง Passkey และติดตั้ง"

เบราว์เซอร์จะให้อุปกรณ์สร้าง Passkey ผ่าน Touch ID, Windows Hello, security key หรือผู้ให้บริการ Passkey เจ้าอื่น Passkey นี้บันทึกในชื่อ "Primary passkey" และใช้ได้กับชื่อโฮสต์ของ CMS เท่านั้น ให้สร้างในหน้าต่างเบราว์เซอร์ปกติ เพราะ Passkey ที่สร้างในหน้าต่างส่วนตัว (private หรือ incognito) อาจหายไปพร้อมหน้าต่าง แล้วเว็บจะเหลือ Passkey ที่ไม่มีเบราว์เซอร์ไหนใช้ได้

เมื่อสร้าง Passkey สำเร็จ ตัวช่วยจะบันทึกการติดตั้งและพาคุณเข้าสู่ระบบไว้เลย ถ้ากดยกเลิกหน้าต่างยืนยันของอุปกรณ์ ตัวช่วยจะแจ้งให้ทราบ กด "สร้าง Passkey และติดตั้ง" เพื่อลองใหม่ หรือกด "ยืนยัน token ใหม่" เพื่อกลับไปขั้นที่ 4 ถ้าสร้าง Passkey ได้แล้วแต่บันทึกการติดตั้งไม่สำเร็จ ปุ่มจะเปลี่ยนเป็น "ลองบันทึกการติดตั้งอีกครั้ง"

## ขั้นที่ 6: Recovery codes

ตัวช่วยแสดง recovery code สิบรหัส แต่ละรหัสใช้ได้ครั้งเดียว และจะแสดงให้เห็นแค่ครั้งนี้ กด "คัดลอก" หรือ "ดาวน์โหลด .txt" (ไฟล์ชื่อ `tomecms-recovery-codes.txt`) แล้วเก็บไว้ที่อื่นที่ไม่ใช่อุปกรณ์เครื่องที่มี Passkey

ติ๊ก "ฉันเก็บ Recovery codes ไว้ในที่ปลอดภัยแล้ว" แล้วกด "ไปที่ Admin" คุณจะเข้าหน้าแอดมินตาม path ที่เลือกไว้ และเข้าสู่ระบบอยู่แล้ว

วันไหนที่ไม่มี Passkey อยู่ใกล้มือ ใช้ recovery code ที่ `/recovery` เพื่อลงทะเบียน Passkey ใหม่และกลับเข้าระบบได้
