# TomeCMS 1.5.0

Date: 2026-09-30
Status: Design, for the owner's review before planning
Branch: work is based on `develop` (1.4.0 at the time of writing).

1.5.0 collects eight changes the owner asked for after looking at 1.4.0 on a real site. One
is a feature with a migration (hiding a post's cover), one is a new component (a date and time
picker), and the rest correct or finish the 1.4.0 admin refresh. They ship together because
they touch the same screens and the same stylesheet.

## What was decided before this was written

- **A post can hide its cover in the article, and shows it by default.** Hiding it removes the
  cover from the top of the article only; the home page card and the image shared with a link
  (`og:image`) keep using it. (Asked and chosen.)
- **No control in the admin opens a picker drawn by the operating system**: no native `<select>`
  list, no native calendar, no native colour wheel. (The owner's instruction, "in every place".)
  The one exception the web itself imposes is the file chooser behind "Upload", which no page can
  replace; the button the owner presses is already ours.
- **The date and time picker is built here**, not taken from a library, like `UiSelect`. (Asked
  and chosen: no new dependency, and full control of Buddhist-era years and the keyboard.)
- **A save button carries its own state**: the spinner while saving, and "Saved" on the button
  after success until something on the form changes again, when it reads "Save". (The owner's
  instruction.)
- **The row menu ("…") closes when you press outside it**, and looks like the other menus. (The
  owner's instruction.)
- **The main column is lighter than the sidebar.** Proposed by Claude as the answer to the
  owner's "the shell should differ from the navigation"; the owner has not chosen yet and may
  change it in review. Before-and-after screenshots come first in the plan.
- **The two notes on the Plugins screen are repaired** as described below. Proposed; the owner
  agreed the screen is broken and has not yet approved the fix.
- **Uploading in the File Manager takes several files at once and lets the owner choose their
  folder**, and the upload button loses the ring it keeps after a click. (The owner's instruction.)

## 1. Hiding a post's cover

### Data

Migration `027_post_show_cover`: `alter table posts add column show_cover boolean not null
default true`. Every existing post keeps showing its cover. Pages have no cover and are not
touched.

The value belongs to an edition, like `cover_media_id`: the Thai and English editions choose it
separately. Creating a translation or duplicating a post copies it with the cover
(`src/server/content/posts.ts`, where `cover_media_id` is copied today).

### Admin

In the post settings drawer (`PostSettingsDrawer.tsx`), under the cover picker, a checkbox:

| Key | English | Thai |
|---|---|---|
| `drawer.showCover` | Show the cover at the top of the post | แสดงภาพปกที่หัวบทความ |
| `drawer.showCoverHint` | The home page and shared links still use it. | หน้าแรกและลิงก์ที่แชร์ยังใช้ภาพนี้อยู่ |

It is checked by default and shown only while a cover is chosen; the value is kept when the cover
is removed and comes back with it. It saves through the same autosave as the other drawer fields.

### Themes

Paper (`parts/PostArticle.astro`) and Plain (`Post.astro`) read one value:
`const cover = post.show_cover ? post.cover_image : null`, and use it both for the `<img>` and
for the choice they already make between `content_html` and `withLeadImage(content_html)`. With
the cover hidden, the first image in the body takes `fetchpriority="high"`, as it does today for
a post with no cover, so the largest paint does not slow down. The home card
(`paper/Home.astro`) and `og:image` (`[slug].astro`) keep reading `cover_image`.

The admin preview uses the theme's own template and follows automatically.

### Headless API

`/api/v1` posts gain `showCover: boolean` beside `coverImage` (`public-schemas.ts`,
`serialize.ts`, `openapi.ts`). The change is additive.

## 2. No operating-system pickers

Every place found in the code, and what replaces it:

| Where | Today | Replaced by |
|---|---|---|
| Posts and Pages, language filter (tab row) | native `<select>` (introduced in 1.4.0) | `UiSelect` with a new `submitOnChange` prop |
| Redirects, "Goes to" | native `<select>` | `UiSelect` |
| Post settings, "Publish at" | `datetime-local` | `UiDateTime` |
| Page settings, "Publish at" | `datetime-local` | `UiDateTime` |
| Maintenance, countdown end | `datetime-local` | `UiDateTime` |
| Home slides, starts and ends | `datetime-local` ×2 | `UiDateTime` |
| Plugin settings, colour fields (Sticky Banner) | `type="color"` | a hex text field with a swatch |

Already ours, checked: every confirmation dialog (`confirmUi`), the public language switcher, the
public and admin theme toggles (a custom popover over native radios, which draws no picker).

### `UiSelect` and `submitOnChange`

A new boolean prop. When an option is chosen (a click, or Enter on the active option) and it
differs from the current value, the component calls `requestSubmit()` on its closest `<form>`.
Arrow keys only move the highlight inside the open list, so a keyboard user can step through the
options without leaving the page, which is what the 1.4.0 keyboard handling was for. That
handling, the "Show this language" button and the `filters.showLanguage` copy are removed.

The admin needs JavaScript throughout (the editor, the lists, every form is an island), so the
list filter's no-script path goes with the native select. A visually hidden label names the
control ("Language").

### `UiDateTime`

A new component, `src/components/admin/UiDateTime.tsx`, beside `UiSelect` and in its visual
language.

- **Value.** The same string a `datetime-local` holds (`YYYY-MM-DDTHH:mm`, the wall clock), so
  `toLocalInput`/`fromLocalInput` in `src/lib/local-datetime.ts` and every caller keep their
  conversions. Props: `id`, `value`, `onChange(value)`, `locale` (`'en' | 'th'`), `min?`,
  `required?`, `disabled?`, `invalid?`, `ariaDescribedBy?`, `name?` (renders a hidden input, for
  the forms that submit natively).
- **Trigger.** A button styled as `.admin-control` showing the chosen moment formatted for the
  owner's language (`Intl.DateTimeFormat`, so Thai shows the Buddhist-era year, as the admin's
  dates already do) or a muted placeholder ("Choose a date" / "เลือกวันที่").
- **Panel.** A non-modal popover placed with the same logic `UiSelect` uses (extracted into a
  shared `placePopover` helper so the two cannot drift): a month heading with previous and next
  buttons, a seven-column grid of day buttons starting on Sunday, today marked with a ring, the
  chosen day filled with the accent; below it, hour and minute fields (24-hour, two digits,
  numeric keyboard on a phone) and, when the field is not `required`, a "Clear" button; "Done"
  closes it.
- **Keyboard.** The grid is `role="grid"` with a roving tab index: arrows move a day, Page Up and
  Page Down a month, Home and End the start and end of the week, Enter or Space choose. Escape or a
  press outside closes the panel and returns focus to the trigger. Days before `min` are disabled.
- **Copy.** Month and weekday names come from `Intl`; the few words (`dateTime.placeholder`,
  `previousMonth`, `nextMonth`, `hour`, `minute`, `clear`, `done`) are admin copy in both locales.

### Colour fields

`type="color"` becomes a text field (`#rrggbb`, lower-cased on blur) with a swatch of the colour
beside it; a value that does not match `COLOR` (`src/server/plugins/store.ts`) shows the field's
error and blocks the save, which the server already refuses. No popup of any kind.

### A guard

`tests/unit/admin-surface-tokens.test.ts` fails on any `<select`, `type="date"`,
`type="datetime-local"`, `type="time"`, `type="month"`, `type="week"` or `type="color"` in
`src/components` and `src/pages`, so the rule holds after 1.5.0. `DESIGN.md`'s "Admin Surface"
records it with the file-chooser exception.

## 3. Save buttons carry their state

One component, `src/components/admin/SaveButton.tsx`, used by every form that saves with a button:

| Form | File |
|---|---|
| Settings | `SettingsForm.tsx` |
| Profile | `ProfileForm.tsx` |
| Maintenance | `MaintenanceForm.tsx` |
| Navigation ("Save menu") | `NavigationManager.tsx` |
| Home slides | `SlidesManager.tsx` |
| Plugin settings drawer | `PluginManager.tsx` (`PluginSetUp`) |
| File details dialog | `MediaLibrary.tsx` |

States: `idle` (nothing changed since load: "Save", disabled), `dirty` ("Save", enabled),
`saving` (the spinner inside the button, as `aria-busy` draws it today), `saved` ("Saved" with a
check icon, disabled), which lasts until the form changes again and it becomes `dirty`. A failed
save returns to `dirty` and shows its error where it does today.

- The button keeps one width in every state: both labels are laid in the same grid cell and the
  one not shown is `visibility: hidden`, so nothing beside it moves.
- The words a screen reader needs still arrive: a visually hidden `role="status"` beside the
  button says "Saved" or "Saving", and errors keep their `role="alert"`.
- The separate status lines these forms print today ("Saved.", "บันทึกแล้ว", "Unsaved changes",
  "No unsaved changes") go; the button says it. The File details dialog gains the draft-versus-
  saved comparison it lacks, so it can be `idle`.
- Copy: the existing `save` keys stay; one shared `shell.saved` ("Saved" / "บันทึกแล้ว") serves the
  button. The now-unused status keys are removed in both locales.
- Out of scope: the editors' Publish and Update, which have their own autosave indicator, and
  action buttons that are not saves (add a redirect, create a category, sign in).

## 4. The row menu

`.admin-story-menu` (Posts, Pages) and the File Manager's folder menu are `<details>` menus.

- **Closing.** A shared `src/lib/details-menu.ts` wires, once per page: a press outside an open
  menu closes it; Escape closes the menu that holds focus and returns focus to its summary;
  opening one closes any other. `MediaLibrary.tsx` drops its own closer for it. Choosing an item
  closes the menu (the list code already does after an action succeeds).
- **Trigger.** A 40px ghost icon button (44px on a coarse pointer): no fill at rest, `paper-3`
  under the pointer and while open, the focus ring only for the keyboard (`:focus-visible`) and
  drawn inside the button, as the folder menu's is.
- **Panel.** A hairline `--color-rule` border instead of `--color-rule-strong`, `--shadow-float`,
  8px corners, 4px from the trigger, `min-width: 11rem`. Items are 36px tall with a fine pointer
  and 44px with a coarse one, with a `paper-2` hover. "Delete" is separated by a rule above it and
  keeps the error colour.

## 5. The main column is lighter than the sidebar

`.admin-shell-main` takes `--color-paper` (white in light, 26.5% in dark); the sidebar stays on
`--color-paper-2`. The work in front of the owner is the lightest surface in both themes, and the
sidebar reads as the desk it sits on. No token is added: the token file already calls
`--color-paper` the raised surface and `--color-paper-2` the page behind it.

What follows it: the save bar's translucent fill mixes `--color-paper`; the phone bar and the
footer sit in the main column and take it; the skeleton's page matches. Cards stay `--color-paper`
with their hairline, so on the lighter column they are held by the rule and their grey cover
area; the plan's screenshots decide whether a card needs its rule stepped to `--color-rule-strong`.

The owner reviews before-and-after screenshots at 1440 in both themes before the change is kept.

## 6. The Plugins screen's notes

- **"Where plugins come from"** leaves the plugin grid: it is not a plugin, and as a grid cell it
  stretched to the tallest card's height with its text centred. It becomes a note below the grid.
- **"A plugin cannot lock you out"** follows it, and both are one note style: a 2px accent bar,
  a 16px display heading, one sentence in `--color-ink-2`, as tall as their words, 32px below the
  grid and 24px apart. Its heading is 16px again: `.admin-card h2`, later in the file, was beating
  `.admin-card--note h2`; the note rule gains the specificity to win, and a unit test pins it.
- The accent bars that are 3px (the notes, the Themes source card, the migrations and maintenance
  notices) become 2px, the width `DESIGN.md` records for bars.
- The Themes screen's "Where themes come from" and status line are checked in the screenshots and
  given the same treatment if they show the same fault.

## 7. Uploading several files into a chosen folder

Today the File Manager's upload button takes one file and files it silently into whatever folder
is on screen, and after the operating system's file chooser closes, the button keeps a focus ring
(`.media-upload:focus-within` fires for the hidden input, however it was focused).

- **The ring.** `.media-upload:has(input:focus-visible)` replaces `:focus-within`: the ring shows
  when the keyboard reaches the button and not after a click.
- **Several files.** In the File Manager (manage mode) the file input takes `multiple`. The picker
  used from a cover or a block (select mode) stays single: it hands one file back to its caller.
- **An upload panel.** Choosing files opens a dialog of ours (the admin dialog surface, like the file
  details dialog) listing each file with its name, size and type, and, above them, a **Folder**
  `UiSelect` whose default is the folder on screen ("Unsorted" when "All files" is on screen). The
  owner can remove a file from the list, change the folder, and press "Upload 3 files" /
  "อัปโหลด 3 ไฟล์" (the count follows the list). Files the library refuses by type or size are
  marked in the list before anything is sent, using the checks `uploadFile` already makes.
- **Progress.** Files go up two at a time through the existing `uploadFile` (presigned upload, then
  finalise). Each row shows its own progress bar and ends with a check or an error; one failure
  does not stop the others, and a failed row offers "Retry". The panel's button reads "Done" when
  every file is settled; closing reloads the grid on the chosen folder so the new files are in view.
  Closing while files are uploading asks first (with `confirmUi`), since the rest would be dropped.
- **Copy** (both locales): the panel title, "Folder", "Upload {count} files", "Remove", "Retry",
  "Done", "Uploaded", and the close-while-uploading question.
- **Server.** Nothing changes: `uploadFile` already sends `folderId` per file.

## 8. Testing

- Unit: the migration inventory (`npm run check:inventory`); `show_cover` read, saved, defaulted
  and copied on translate and duplicate; the public schema and OpenAPI; both themes render no
  `.post-cover` and a lead `fetchpriority` with the cover hidden; `UiSelect` submits its form on a
