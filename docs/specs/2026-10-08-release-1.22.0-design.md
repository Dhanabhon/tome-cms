## 1. The list's loose ends (from the 1.21.1 review)

`src/components/admin/UiSelect.tsx` and its tests:

1. **Pointer flag.** The scroll effect returns on `!open` before it clears `pointed`, so a hover change
   committed in the same render as a close leaves `pointed` set and the next open skips scrolling to
   the chosen option. Clear the flag first, then return.
2. **Home and End.** They line the row up with the padding box's edge, so the list's own padding stays
   hidden at the top or bottom. Index 0 scrolls to 0; the last row scrolls to the end.
3. **Test guard.** `tests/e2e/passkey-installer.spec.ts` waits on `animation.finished` without
   `.catch(() => undefined)`; add it, as the other specs do.

## 2. Tailwind CSS 4

Today: `tailwindcss` 3.4 through PostCSS (`postcss.config.mjs` with `autoprefixer`), a JS config
(`tailwind.config.mjs`: screens, fontSize, colours, fonts, radii, typography — all values read the
tokens in `src/styles/installer-tokens.css`), `@tailwindcss/typography` 0.5, and `@tailwind` /
`@apply` in `src/styles/global.css`. Its eight advisories (braces, micromatch, chokidar, fast-glob,
postcss-selector-parser, postcss-nested, typography) are the only ones left in the production audit.

| Question | Ruling |
| --- | --- |
| Goal | Tailwind 4 with **no visible change**: every admin screen, the installer and the three themes look the same before and after, in light and dark, at phone, tablet and desktop widths. |
| Wiring | Tailwind 4's PostCSS plugin (`@tailwindcss/postcss`) or its Vite plugin, whichever fits Astro 7 here with the least change. `autoprefixer` goes if Tailwind 4 makes it redundant. |
| Config | Prefer the smallest correct move: keep `tailwind.config.mjs` through `@config` if Tailwind 4 honours every key it uses, otherwise move it to CSS (`@theme`). Either way the values still come from the tokens in `installer-tokens.css` (one source), and `scripts/check-design-tokens.mjs` keeps working (or is updated to read the new place). |
| Content | Tailwind 4 finds sources itself; make sure it scans exactly what 3 did (`src/**/*.{astro,html,js,jsx,md,mdx,ts,tsx}`), no more (no `node_modules`, `dist`, `website/`). |
| Breaking defaults | Tailwind 4 changes defaults (border and ring colours and widths, placeholder colour, button cursor, `shadow-sm`/`rounded-sm`/`outline-none`/`ring` names, `space-*` and `divide-*` selectors, `hover` only on hover-capable devices, preflight details). Find every use that would change and keep today's look — rename classes, or set the old default once. Check the upgrade guide; the official upgrade tool may help but its output is reviewed, not trusted. |
| Typography | `@tailwindcss/typography` on a version that supports Tailwind 4, wired with `@plugin`; the `prose` overrides (colours, inline-code backticks off, h2/h3 sizes) keep their effect. |
| Production CSS | The production build must keep every declaration: Tailwind 4 minifies through Lightning CSS. An earlier minifier folded `animation-timeline` into a shorthand Chrome drops (scroll timelines). Check the built CSS for every `animation-timeline`, `view-timeline`, `@supports`, `@container`, `@property` and nesting the sources have, and for dark-mode and reduced-motion rules. |
| Proof | Screenshots of every admin screen (`ADMIN_SHOTS`), the installer and every theme page, before and after, compared; any pixel difference is explained or fixed. The full e2e suite passes. `npm audit --omit=dev` reports no advisory. |
| Docs | `contributing/project-layout.md` and `extending/themes.md` (en + th) say Tailwind 4 and how it is wired; README's audit sentence goes back to "no advisory". |
