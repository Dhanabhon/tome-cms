# TomeCMS 1.25.0 — a page can show a list of posts

Date: 2026-11-03
Status: approved by the owner on 2026-11-03 ("ตกลง"). Section 1 is what the owner ruled in the grilling
rounds; everything below it is the controller's design. Releasing is a separate order.

## 1. The owner's rulings

| Question | Ruling |
| --- | --- |
| Purpose | A page with its own text and then posts, such as a portfolio page. A real page is the measure. |
| Where | A block in the page body. Any position, several per page. Pages only, not posts. |
| Source | One per block: hand-picked posts, or a whole category. Both on one page means two blocks. |
| Hand-picked | The owner's order, set with up and down buttons. |
| Category | New posts appear by themselves, newest first. |
| Count | Category default 6. Both sources at most 24 per block. |
| "See all" | A link to the category page, only when the category holds more than the block shows. No paging inside the page. Hand-picked blocks have no link. |
| Layout | Grid of 2 or 3 columns, or a list. New blocks start as a 3-column grid. A column count is a maximum: narrow screens use fewer, phones one. |
| Cards | The same card as that theme's home page. Plain's has no cover, so its grid is text only. |
| Languages | Each language's page holds its own block. A block shows the edition in its page's language and skips posts without one. |
| Missing posts | Deleting or unpublishing is never blocked and gives no warning. The public page leaves it out; a block with nothing left shows nothing; the editor says what no longer shows. |
| Deleted category | Its posts move to the default category as today, and the block is empty. |
| Export and import | Import repoints blocks at the new ids. The readable `.md` gets a short note. |
| MCP | A block shows as `{{tome:block N}}`: an agent can move or remove it, not create or edit one. |
| Editor | A summary box (source, layout, titles) with a settings button. No theme look-alike; the existing preview shows the real thing. |
| Picker | A window to search by title and tick posts. |
| Heading | No field. The owner places a heading block above it. |
| Public API | A page's `contentHtml` carries no post list. |
| Sitemap | A page's date stays its own, unmoved by new posts in a block. |

Not in this release: colours or spacing per block; showing or hiding cover, date or excerpt; 4
columns or a block wider than the page column; agents creating blocks.

## 2. The node

A new Tiptap node `postList` in `src/lib/editor-post-list.ts`, shared by client and server as
`video` and `attachment` are, and added to `extensions` in `src/server/content/editor.ts` and
`buildExtensions` in `DocumentCanvas.tsx`.

```ts
interface PostListAttrs {
  source: 'posts' | 'category';
  postGroupIds: string[];      // post translation groups, in order; [] unless source is 'posts'
  categoryId: string | null;   // null unless source is 'category'
  limit: number;               // 1-24; category only, 6 by default
  layout: 'grid-2' | 'grid-3' | 'list';
}
```

| Question | Design |
| --- | --- |
| Why translation groups | A group names a post across languages, and it is what `post_category_assignments` already keys on. Each language's block resolves it to that language's edition. |
| Validation | `postListAttrs(value)`, like `videoAttrs`: an allowlist of keys, UUIDs, at most 24 ids without duplicates, `limit` in range, `source` agreeing with its fields; anything else is `null`. `normalizeMediaNodes` throws `ValidationError` on `null` and stores only what it returns. Existence is not checked: a stale id shows nothing, and `live()` and the owner filter guard every read. |
| Top level only | A placeholder inside a quote or a table cell could not be split out (section 3). The node takes its own group and the document's content becomes `(block\|postList)+`, so ProseMirror itself refuses a drop into a quote. This replaces StarterKit's document on both sides. The server also refuses a node nested anywhere else. |
| Pages only | `prepareContentWithFiles` is shared, so `posts.ts` refuses a document holding a `postList`: `ValidationError` from the admin and MCP, `content_invalid` from an import. `DocumentCanvas` takes a `pageLocale` prop that only `PageEditor` sets; it names the block's language and gates the slash item and the `+` menu entry. |
| Stored HTML | `renderHTML` emits an empty `<div class="tome-post-list" data-post-list="{json}"></div>`. The sanitizer allows that one class on `div` and strips `data-*`, so stored HTML holds only `<div class="tome-post-list"></div>`, with nothing a writer typed. The data attribute exists for the clipboard: `parseHTML` reads it through `postListAttrs`, so copy and paste inside the editor keeps a block and a paste without it makes none. |
| `hasMeaningfulContent` | Counts `postList`, so a page holding only a block can be published. |
| Public API | `contentHtml` has the empty div, invisible. `contentJson` carries the attrs: opaque ids only, which may name drafts and reveal nothing about them. |

## 3. Rendering a page

A new `src/server/content/post-lists.ts`, called by `[locale]/[slug].astro` and
`admin/pages/preview/[id].astro`. `getPublishedPage` and the API do not change.

```ts
interface ResolvedPostList {
  layout: PostListAttrs['layout'];
  posts: ThemeHomePost[];
  moreHref: string | null;
}
resolvePostLists(page): Promise<ResolvedPostList[]>   // document order, one entry per node
```

| Question | Design |
| --- | --- |
| A page without blocks | No extra query, and the same HTML as today. |
| Category source | Read the category by id for its name and slug, then `listPublishedPosts({ locale, category: name, take: limit })`, so the rules are the category page's by construction. `moreHref` is `categoryPath` when `hasMore`, except for the default category, which has no page. |
| Hand-picked source | One new query: `live()` posts of that locale and owner in those groups, through `enrichPosts`, put back in the block's order. |
| Failure | A failed read fails the page as a failed page read does today (the route's 500). A wrong list cached for five minutes would be worse. |
| Preview | Lists show published posts only, as the public page will. |
| Theme contract | `ThemePageProps` gains optional `postLists`, `profile` and `settings` (timezone, site name), the last two read only when a page has a block. Paper's and Almanac's cards need them. |
| Splitting the body | `pageBodyParts(html, lists)` in `editor-content.ts` runs after the existing rewrites (`demoteH1`, `withResponsiveImages`, `withLeadImage`) and splits on the exact placeholder into text and lists in order. Empty text parts are dropped. A placeholder with no matching list draws nothing. |
| Why separate containers | Each text part gets the theme's own prose `div`, with the list as a sibling. Inside `.prose`, `.post-body` or `.almanac-prose`, a card would inherit the body's rules for `h2`, `img` and `p`. |
| Caching | No change. Any admin write clears the page cache, and `nextScheduledPublish` already expires a page when a scheduled post goes live. |

| Theme | Card | Change |
| --- | --- | --- |
| Paper | Inline in `Home.astro` (lines 264-285) | Move to `parts/PostCard.astro` with the props it reads; `Home` uses it. |
| Plain | Inline `<li>` in `Home.astro` (lines 72-76) | Move to `parts/PostCard.astro`. |
| Almanac | Already `parts/PostCard.astro` | Reused. |

Each theme gains `parts/PostList.astro`, with the layout on its wrapper. Moving the cards must not
change either home page; the home screenshots are compared before and after.

| Question | Design |
| --- | --- |
| Column | The block stays in the page column: Plain 44rem, Paper 48rem, Almanac 44em at 18 px. |
| Grid | `grid-3` is three columns from 48rem of viewport, two from 40rem, one below. `grid-2` is two from 40rem, one below. Tracks are `minmax(0, 1fr)`. |
| List | One column. With a cover (Paper, Almanac), the cover sits beside the text from 40rem and above it on a phone. Plain has none. |
| Images | `sizes` follows the layout. All covers are `loading="lazy"`: a block rarely holds the largest paint. |
| Headings | Card titles keep their level on the home page (`h2`, or the card's own). A level inside the body may not follow the owner's headings; checked with an accessibility scan. |
| "See all" | `publicCopy` gains `seeAll` (th/en), a plain link below the list. |

The "list" layout beside a cover is the controller's reading of "รายการ", and the most likely place
for the owner to want something else.

## 5. The editor

| Question | Design |
| --- | --- |
| Insert | A slash item and a `+` menu entry "รายการบทความ / Post list", hidden in a table and in the post editor. Inserting opens the settings window at once; cancelling inserts nothing. |
| Box | A node view like `video`'s: source, layout, and the titles or the category name. Rows that will not show are marked, with the reason. Empty states say so. |
| Settings | A dialog with the source choice, the picker or a category select (`UiSelect`), the count, and the layout. Keyboard and focus as the media picker's. |
| Picker | Search filters on the client, over this language's posts of any status, with drafts labelled: a draft may be chosen and shows when it is published. Ticking adds to the end; up and down buttons order. The 24th tick disables the rest and says why. |
| New endpoint | `GET /api/admin/post-list-options?locale=` returns `{ groupId, title, status }` per post in that locale, columns only, never `content_json`, since `listPosts` reads whole rows. The box uses the same answer to name its rows, so a missing row is a group not in it, or one whose status is not live. Owner-only like the other admin reads, and uncached. |
| Categories | The existing `GET /api/admin/categories`. |

## 6. Export, import and MCP

| Question | Design |
| --- | --- |
| Export `.tome.json` | `relinked` adds `categoryName` to a category block's attrs, read from the same transaction's categories. `postGroupIds` stay, because `.md` front matter's `translation` carries the same id. |
| Import | Group ids are assigned for every planned item before any item is written, so a page imported before its posts can already name them. `relinkExact` then maps `postGroupIds` through those groups and `categoryName` to a category id, dropping `categoryName`. |
| Import, category with no posts | The plan adds a block's category to `categoriesToCreate` when it is absent, with its archived details. |
| Import, post skipped | A post skipped because it already exists here resolves to the existing post's group by locale and slug. An id that resolves to nothing is dropped from the block. |
| Readable `.md` | One note line, as `TABLE_NOTE` is, because `documentToReadableMarkdown` has no database. An `.md`-only import therefore gets that text and no block. |
| MCP | `standsIn` returns a new kind `postList` with a label such as "Post list (3 posts)". `markdown-in.ts` keeps its rules: blocks return by number, a new draft holds none. |

## 7. Rollback

No migration, so nothing about the database blocks going back.

- An update that fails its checks rolls back before anyone can have written a block.
- On an older version by any other route, public pages stay up: its sanitizer strips the class and
  leaves an empty `div`, so the list is simply gone.
- That older server refuses to re-save such a page ("unsupported editor structure", from reading
  `renderEditorHtml`), and its editor may fail to open it. Not tested, and the stored document is
  not altered either way, so the block returns with the newer version.

## 10. Review focus

The inputs most likely to bite that the rulings do not spell out:

1. Two blocks in a row: nothing between them, and spacing must still read as two lists.
2. A body that starts with a block: `withLeadImage` must not reach into it, and a page with only a block needs no empty prose `div`.
3. Thai titles in a narrow card at 320 px: no overflow.
4. A category renamed after the block was made: the block holds the id, so it follows.
5. A page opened in the editor by an MCP session at the same time: blocks return by number, so moving one must not lose its attrs.
