# TomeCMS 1.20.0 — images at the size they are drawn, a page per category, and the small things

Date: 2026-10-07
Status: approved by the owner as proposed ("ตกลง"), including releasing it when done. The rulings
below are the proposal the owner accepted; details beneath them are the controller's.

## 1. Responsive images (`srcset`)

| Question | Ruling |
| --- | --- |
| When | At the end of an image upload, from the buffer the server already holds to inspect it (`finalizeUpload` → `verifiedImage`), and in `importImage` / `createMediaFromBytes`. One image at a time. |
| Sizes and format | Widths **480, 960, 1600** px, only those narrower than the original; **WebP** (quality ~78, metadata stripped, orientation applied). No AVIF (too heavy to encode on a 1 GB server). |
| Animated images | No variants (animated GIF/WebP keep the original). |
| Images already uploaded | A background backfill after the app is ready (as the 1.16.4 brand-SVG backfill rides on readiness), one image at a time; until an image has variants, pages use the original. |
| Storage | A new table `media_variants (media_id → media_items.id on delete cascade, width, object_key unique, size_bytes, created_at; unique (media_id, width))`. Each variant is its own object under a key that fits the existing grammar (`createObjectKey(owner, 'image/webp')`). Deleting a media item deletes its variants' objects too; the cleanup script, reset's `knownObjects` and backup cover them (backup copies the bucket; keys fit `isTomeObjectKey`). Export bundles originals only; import regenerates variants. |
| Address | `/media/<id>?w=<480|960|1600>` → 302 to that variant's object when it exists, otherwise to the original. Any other `w` → the original. Same cache headers as today. |
| Where it is used | Body images (rewrite of `<img src="/media/<id>">` in the public HTML, next to `withLibraryAlts`), post covers, home cards and slides in Paper, Plain and Almanac: `srcset` of the existing variants plus the original's own width, a `sizes` that matches each layout, and the real `width`/`height` from the media item. |
| Failure | A variant that fails to generate never fails the upload; it is logged and left to the backfill. |

Generation must not hold more than one image's working memory at a time (an in-process queue or
sharp `concurrency(1)` for this work), and must use the same `limitInputPixels` as `inspectImage`.

## 2. Category pages

| Question | Ruling |
| --- | --- |
| Address | `/th/category/<slug>` and `/en/category/<slug>`. |
| Slug | New `categories.slug`, unique per owner, generated from the name with the existing content-slug rules (Thai allowed, as since 1.15.0), editable in the category manager. The migration fills a slug for every existing category. |
| Description | New optional `categories.description_th` / `description_en` (≤ 160 chars), edited in the category manager; shown on the category page and used as its meta description (fallback: the other language's, then a sentence built from the name and site). |
| Name | Still one name for both languages. |
| Page | The theme's home listing filtered to the category (each theme already renders an active category), with its own heading, `<title>`, description, canonical, hreflang alternates (locales that have posts in it), pagination and `BreadcrumbList` Home › Category. A category with no live post in that locale answers 404. |
| Old links | `/<locale>?category=<name>` → 301 to the category page (case-insensitive name match); an unknown name → the home page as today. |
| Theme links | Category chips/filters point to category pages; Paper and Plain post pages make category names links (Almanac already links). |
| Default category ("Uncategorized") | No page (404), not in the sitemap, no breadcrumb level. |
| Sitemap | Each category page with live posts, per locale. |
| Breadcrumb on posts | Home › first non-default category › post; Home › post when there is none. |
| API | `/api/v1` categories and embedded post categories gain `slug` (additive); OpenAPI updated. MCP unchanged unless it lists categories (then add slug). |
| Page cache | Category pages are public pages: cached and cleared like the others. |

## 3. Small fixes

1. `/add-device`: when the link dies between options and verify (cancelled, superseded, spent by recovery,
   expired), show the expired message, not "server error".
2. The Security screen counts the link's remaining time from the server (`expiresInSeconds` in the POST
   answer), not from the client clock.
3. Creating a device link uses its own rate-limit bucket, not `signin`.
4. `/api/v1` site description: the default language's, falling back to the other language's when empty.
5. Docs screenshots re-shot at the end (`npm run docs:screenshots`), alt texts updated where they changed.

backfill), English and Thai; the requirements page notes the extra storage (about 3 small WebP files per image).
