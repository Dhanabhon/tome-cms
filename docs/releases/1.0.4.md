# TomeCMS 1.0.4

Date: 2026-09-28
Status: Stable release; tagged and published as a GitHub release

TomeCMS 1.0.4 makes deleting a file, removing a site logo and making new recovery codes work on
a managed install, and tidies the file library's folders: each folder's rename and delete now sit
in a menu on its chip.

## Upgrading

- **A managed install** updates from "System" in the admin, as
  [Updating](https://dhanabhon.github.io/tome-cms/running/updating/) describes. A server
  installed with 1.0.1 or 1.0.2 adds the init first, as the [1.0.3 notes](1.0.3.md#upgrading)
  say, if it has not already. There is no migration, no new setting and no new runtime
  dependency.
- **A build from source** upgrades in place by running the deploy helper again.

`deploy/cloud-init.yaml` now installs 1.0.4.

## Requests the admin sends

On a managed 1.0.3 server, deleting a file in the library ended with "The request could not be
completed." and the file stayed. Astro checks the origin of every `POST`, `PUT`, `PATCH` and
`DELETE`: one with no content type is refused unless its `Origin` equals the address Astro sees.
Behind Caddy that address is `http://`, while the browser sends `https://`, so Astro answered
with a plain-text `403` that the admin could not read. On the server, the same `DELETE` with no
content type got that `403`, and with `application/json` reached TomeCMS.

Three admin requests had no body and no content type, and all three failed that way on a managed
install:

- deleting a file in the file library
- removing a site logo
- "Verify and create new codes" for recovery codes

All three now send `application/json`, and a unit test fails on any request the admin makes to
change something that names no content type. The browser tests run over plain HTTP, where the
two addresses agree, so they never met it. Nothing was changed by a refused request.

## The file library

Each folder had two visible buttons after its chip, "Rename" and "Delete" followed by the
folder's name, so two folders ran to a line of repeated names. A folder is now one pill: its name,
and a "..." that opens a menu with "Rename" and "Delete", the same menu the posts list uses. The
selected folder outlines the whole pill. On a phone, where the folders are a list to choose from,
the chosen folder's "..." sits beside that list. Escape closes the menu.

## The documentation

Troubleshooting covers "The request could not be completed." for those three actions, and the
file library page describes the folder menu. English and Thai.

## For theme authors, plugin authors and headless sites

Nothing a theme, plugin or headless site depends on changed.

## Validation boundary

- `npm run check` passes, and the documentation site's check and build pass.
- `npm run test:unit`: 600 tests, all passing, among them the scan of the admin's requests,
  which listed exactly the three above before the fix.
- The folder menu was checked in a real signed-in admin, on its own disposable database, at
  1440 and 375 pixels wide: the menu opens, Escape closes it and returns focus, "Rename" opens the
  field, and "Delete" removes the folder.
- The three requests were not yet run on the managed server after the fix; updating that
  server to 1.0.4 and deleting a file there is their first run.
