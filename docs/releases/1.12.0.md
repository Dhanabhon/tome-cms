# TomeCMS 1.12.0

Date: 2026-10-03
Status: Stable release; tagged and published as a GitHub release

TomeCMS 1.12.0 gives `tome` three commands for building themes and plugins in a source checkout. Nothing changes on a running site, and `/api/v1` is unchanged.

## Upgrading

- **A managed install** updates from "System" in the admin, as
  [Updating](https://dhanabhon.github.io/tome-cms/running/updating/) describes, or with
  `sudo tome update` on the server. There is no migration, so the updater backs up the database
  alone.
- **A build from source** upgrades in place by running the deploy helper again.
- **The updater** stays at 1.5.0. Nothing to upgrade on the server.

`deploy/cloud-init.yaml` now installs 1.12.0.

## Building themes and plugins

These commands run in a TomeCMS source checkout with `npm run tome -- <command>`. They need no
root. On a server, or anywhere outside a checkout, they say "Run this in a TomeCMS source checkout"
and change nothing.

- **`tome theme new <id> [--from plain|paper|almanac]`** copies a working theme under a new id and
  registers it, so it can be chosen under Appearance → Themes. Class names and the body class take
  the new id; a class the core itself styles by keeps its name. A font the source loads is linked,
  not copied.
- **`tome plugin new <id> --hook publicPage|signIn|editorSuggestions [--client]`** writes a plugin
  that does nothing until it is written, and registers it, switched off.
- **`tome check`** checks every theme and plugin:
  1. each directory matches its manifest id;
  2. each is listed in both `manifests.ts` and `registry.ts`;
  3. the required files are there;
  4. settings are well formed, with English and Thai labels;
  5. a plugin implements its hook;
  6. a theme imports nothing from the server;
  7. a theme's CSS keeps raw colours in its token blocks.

  It prints each problem as `path:line: what is wrong`. `npm run check` now runs it, so CI catches
  these before a merge.

Both `new` commands take `--dry-run`, which prints the files and lines it would write and writes
nothing. If a list file is not in the shape they expect, they change nothing and print the lines to
add by hand.

[Starting with tome](https://dhanabhon.github.io/tome-cms/extending/themes/) for themes and
[for plugins](https://dhanabhon.github.io/tome-cms/extending/plugins/) explain the rest.

## Testing

- **Unit tests** for:
  - the id rules;
  - finding the checkout;
  - every rename rule;
  - the list-file edits and their refusals;
  - rollback;
  - `--dry-run`;
  - each plugin skeleton;
  - each `tome check` rule, against a passing and a failing fixture.
- **A build proof** copies the repository to a temporary directory, makes themes from Almanac and
  Plain and a plugin with a client script, then runs `astro check` and `tome check` on the copy.
- **`tome check` passes on today's repository:** three themes and six plugins.
