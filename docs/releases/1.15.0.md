# TomeCMS 1.15.0

Date: 2026-10-04
Status: Stable release; tagged and published as a GitHub release

TomeCMS 1.15.0 tells browsers to use HTTPS, fixes two content bugs, and finishes the design and
touch-screen details that the 1.14.0 review left open. `/api/v1` is unchanged.

## Upgrading

- **A managed install** updates from "System" in the admin, as
  [Updating](https://dhanabhon.github.io/tome-cms/running/updating/) describes, or with
  `sudo tome update` on the server. There is no migration, so the updater backs up the database
  alone.
- **A build from source** upgrades in place by running the deploy helper again.
- **The updater** stays at 1.6.0. Nothing to upgrade on the server.

`deploy/cloud-init.yaml` now installs 1.15.0.

## Added

**HSTS.** On a site whose public address is HTTPS, every answer from the app carries
`Strict-Transport-Security: max-age=31536000`. A browser that has opened the site once over HTTPS
then goes straight to HTTPS for a year, even for an address typed as `http://`, so a network in
between cannot hold it on plain HTTP.
- It has no `includeSubDomains`, so it says nothing about your other host names, and no `preload`.
- The app sends it, not the Caddyfile, so an existing install gets it from this update without
  running `prepare-vps.sh` again.
- The media origin does not send it; the admin's cookies live only on the CMS origin.
- A proxy in front, such as Cloudflare, may add its own HSTS; that does no harm.

## Fixed

**Content.**
- A page an AI makes through MCP (`create_draft`) is in the language it asked for. It used to take
  the site's default language. Posts were already right.
- Saving a post or page keeps its address. A slug that is already valid is kept as it is; before,
  every save split it again into words, so a Thai address stored as one run, from an import or typed
  by hand, changed on an edit that never touched it. A published item left a redirect, but a draft
  did not.

**Themes.**
- **Plain:**
  - a post's h2 and h3 are a clear step apart, 28 and 22 pixels;
  - an article title fills its line before it wraps, as the home lead has since 1.14.1.
- **Plain and Paper:** the footer's © is full size. Google Sans draws it small and raised, so that
  one character is now set in the reader's own interface face.
- **Paper,** with the hero set to "Covers of the newest posts":
  - on a tablet, a long cover title wraps before it reaches the slider's three buttons;
  - on a phone, it sits above them, and the cover is 4:3 so a three-line title fits.

**Touch screens.** On a touch screen, every control in Paper, Almanac, Plain and the admin is at
least 44 × 44 pixels. This covers the site name, menu and footer links, the language and scheme
switches, pills, the author link, search controls, paging, and the admin's buttons, checkboxes and
navigation. With a mouse, nothing changes. Links inside a post's text are left as they are, as the
accessibility guidelines allow.

**The editor.** On a phone, the formatting bar wraps onto a second line instead of cutting off its
align buttons.

## For theme authors

- `--font-system` is a new core token: the reader's own interface face, for a single glyph a web
  font draws badly. Wrap the glyph in `<span class="copyright-mark">` and give that class
  `font-family: var(--font-system)`, as Plain and Paper do for the ©.
- Two new browser gates measure touch targets on the mobile project:
  `tests/e2e/touch-targets-themes.spec.ts` and `tests/e2e/touch-targets-admin.spec.ts`. A control
  under 44 × 44 pixels under `(pointer: coarse)` fails them. Grow it inside
  `@media (pointer: coarse)`, using your theme's field-height token, so a mouse user sees no change.

## Testing

- **Unit:** HSTS on a real middleware answer, including a redirect and a missing address; the slug
  that is kept on save; Plain's heading sizes and title wrap; the © class in both themes; Paper's
  caption room.
- **Integration:** an MCP page in Thai on an English site; a Thai slug kept through a post's and a
  page's update; a reserved page slug still refused.
- **Browser:** the two touch-target gates; a check that every formatting-bar button is on screen on
  a phone; and the theme screenshots, in English and Thai, light and dark, at 320 to 1440 pixels
  wide, with a new "Covers" screen for Paper.
