# TomeCMS 1.8.2

Date: 2026-10-02
Status: Stable release; tagged and published as a GitHub release

TomeCMS 1.8.2 lets an AI app write back a draft that has a picture inside a list item, and builds the
release's arm64 image on an arm64 machine. `/api/v1` and the MCP tools' inputs are unchanged.

## Upgrading

- **A managed install** updates from "System" in the admin, as
  [Updating](https://dhanabhon.github.io/tome-cms/running/updating/) describes. There is no
  migration and no new setting, so the updater backs up the database alone.
- **A build from source** upgrades in place by running the deploy helper again.

`deploy/cloud-init.yaml` now installs 1.8.2.

## A picture in a list item

`get_post` gives an AI app a draft as Markdown, and `update_draft` takes Markdown back. A numbered or
bulleted item holding words, then a picture, then more words was written with the picture on the line
under the words. Markdown reads that line as part of the words' paragraph, so the picture came back
inside a paragraph. The editor holds a picture only as a block, so the write was refused, with a
message about `{{tome:block N}}` lines that did not name the cause. An app could not send back the
Markdown it had just been given; it had to move the picture out of the list first.

Each paragraph an app writes is now split around any picture in it: the words before, the picture,
and the words after, with the line ends left at the cut taken off. The picture stays in its list item,
between the words it stood between. A picture an app puts in the middle of a line is split out the same
way. Markdown import is unchanged.

## The release's arm64 image

The release built both architectures of the image in one job on an amd64 machine, emulating arm64
with QEMU. That died in `npm ci` with "Illegal instruction" on 1.1.2, 1.7.0, 1.8.0 and twice on 1.8.1,
and each of those releases waited on re-runs. Nothing was published by a failed run.

`release.yml` now builds each architecture on a machine of its own kind (`ubuntu-24.04` and
`ubuntu-24.04-arm`), pushes each by digest, and joins them in one index, which it attests as before.
The installer's and the updater's checks are unchanged: the attestation is still signed by
`release.yml` on the version's tag, on a GitHub-hosted runner.

To push the index, the release gives it the version as a tag, `ghcr.io/dhanabhon/tome-cms:1.8.2`.
That tag is only a way to find it: installs and updates take the image by digest, never by tag.

## Testing

- Unit: a draft with a list item of words, a picture and more words is read and written back with
  the picture in the same place and no line end left behind; a picture in the middle of a line stands
  between the words around it.
- Integration: the MCP tools run against a real database as before.
- Unit: the release workflow has no QEMU step, builds amd64 and arm64 on their own runners, and
  publishes only once both are built and joined in one index.
