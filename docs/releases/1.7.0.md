# TomeCMS 1.7.0

Date: 2026-10-01
Status: Stable release; tagged and published as a GitHub release

TomeCMS 1.7.0 lets the owner connect an AI app (Claude or ChatGPT) to their own site. The app can
read the site and write drafts, after the owner allows it with their passkey. It cannot publish,
schedule, delete or upload, and the owner can put back a draft the AI changed. `/api/v1` is unchanged.

## Upgrading

- **A managed install** updates from "System" in the admin, as
  [Updating](https://dhanabhon.github.io/tome-cms/running/updating/) describes.
  - There is **one migration**, `028_mcp`. It adds tables for the MCP clients, connections, codes and
    tokens, and for the undo copies.
  - Because a migration is due, the updater takes a full backup, not a database-only one.
  - No new setting is needed.
- **The new runtime dependency** is `@modelcontextprotocol/server` 2.2.0, pinned exactly.
- **The MCP plugin is off until the owner switches it on.** Until then, every new address answers
  404: `/mcp`, `/oauth/*` and `/.well-known/oauth-*`.
- **A build from source** upgrades in place by running the deploy helper again.

`deploy/cloud-init.yaml` now installs 1.7.0.

## Connecting an AI app (MCP)

"MCP" is a new card on Plugins, marked Official. Its code is part of TomeCMS. The plugin contract does
not change: a plugin still adds no route and reaches no database.

With MCP on, the owner pastes `https://<site>/mcp` into Claude's or ChatGPT's connector screen, or runs
`claude mcp add --transport http tomecms https://<site>/mcp` for Claude Code. Connecting then goes
through these steps:

- **Who the app is.** The app identifies itself by a Client ID Metadata Document or by Dynamic Client
  Registration.
- **Where a sign-in can go.** A sign-in can be sent back only to Claude, ChatGPT, this computer, or an
  address the owner adds in the plugin's settings.
- **The consent screen.** The owner sees the address the approval goes back to, in large type. They
  choose reading only, or reading and writing drafts, and allow it with their passkey again.
- **Tokens.** Access tokens last an hour and refresh tokens 30 days. Refresh tokens rotate on every
  use. A rotated token presented again more than 30 seconds later revokes the connection; inside that
  window it is refused without revoking, so an app refreshing twice at once is not cut off. Only a hash
  of each token is stored.

The card lists each connection, with what it may do and when it was last used, and **Revoke** stops one
at once. "Allow AI to write drafts" switches writing off for every connection without revoking any.
Switching MCP off, from the admin or with `npm run plugin:disable mcp`, stops everything at once.
Switching it on again disconnects every app that was connected before.

## What the AI can do

There are ten tools:
- **Reading:**
  - the site's details;
  - search;
  - lists of posts and pages;
  - a post or page as Markdown, drafts included;
  - categories;
  - the media library.
- **Writing:** creating a draft, which can be the other language of an existing post, and editing a
  draft.

It cannot publish, schedule, unpublish, delete, upload, or change categories, menus or settings.

Some rules keep a draft safe:
- **Blocks Markdown cannot hold.** Videos, file attachments and tables with merged cells reach the AI
  as `{{tome:block N}}` lines, and the same blocks are put back when the lines come back.
- **Formatting Markdown cannot hold.** The AI is told how much text colour, underline and alignment a
  rewrite would drop.
- **Pictures.** The AI may place only pictures already in the library. Any other picture address
  refuses the whole edit, which blocks a prompt-injected image from carrying data out.
- **Editor-valid only.** Every write is checked against the editor's schema before it is stored.
- **Concurrent edits.** An edit made since the AI read the draft is never overwritten: the AI gets a
  conflict instead.
- **Categories.** They belong to both language editions of a post. The AI cannot set them on a
  translation, or change them while either edition is published.

## Put back

When an AI has changed a draft, the editor shows "<app> changed this draft at <time> · Put back".
Put back restores the draft as it was before the AI began. That holds even if the AI then edited it
several times in a row. The undo copy is dropped when the owner puts it back, publishes, or deletes
the draft.

## The admin's own forms behind the proxy

Astro's built-in cross-site form check is replaced by one that compares against the site's public
address. The old check compared against the address the app sees behind Caddy, which is `http://`.
It also refused any form post without an `Origin` header, and that is exactly how an OAuth client's
server calls the token endpoint. Same-site admin forms behave as before.

## Testing

- **Unit:**
  - the origin guard;
  - PKCE, redirect matching and the client-document fetch (public addresses only, a 64 KB cap
    enforced while streaming, no redirects);
  - Markdown in both directions, including the schema check;
  - the fault log, which records stack frames only.
- **Integration (Postgres):**
  - the OAuth round trip;
  - code and refresh-token races and their reuse rules;
  - the authorize rate limit, and that no client is stored before consent;
  - consent checks for owner, same origin and a fresh passkey;
  - all ten tools, including scope, owner isolation, drafts only, translation categories, the update
    freeze and undo;
  - the connections list, Revoke and the clean start.
- **Browser:** switching MCP on, connecting a client, the passkey consent screen at 390 px and
  1440 px, creating and editing a draft over `/mcp`, Put back in the editor, Revoke, and a 401
  afterwards.
- **Not yet run against the real apps:**
  - connecting from claude.ai and from ChatGPT needs a public HTTPS site;
  - it will be done on daedalus and recorded here.
