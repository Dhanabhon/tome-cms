# TomeCMS 0.11.0

Date: 2026-09-24
Status: Release candidate; not tagged for production

TomeCMS 0.11.0 is 0.10.0 plus four things:

- a Stats screen for which articles are read, counted by TomeCMS itself
- a maintenance mode that closes the site to visitors
- a popup plugin
- `paper` showing an author's links as icons

It is the feature freeze on the road to 1.0.0: after it, only fixes until 1.0.0. This is still a
pre-1.0 clean-install line; the 0.2.0 release gates remain open.

## Upgrading

Two migrations, `024_site_maintenance` and `025_content_stats`. Run `npm run db:migrate`, or let
the deploy helper run it. Until they run, the admin names them at the top of every screen, and
the Maintenance and Stats screens cannot load. Public pages still load, and the counts they send
are dropped and logged. An installation created from an earlier version than 0.10.0 still needs
what the [0.10.0 notes](0.10.0.md#upgrading) list.

- One new runtime dependency, `mmdb-lib` (MIT), which `npm ci` installs.
- The release image carries the DB-IP Lite country database at `/app/data/geoip`. An image built
  on your own server does not; see [Stats](#stats).
- Every public page now carries a small script that counts it. A theme, a plugin or an API
  client written for 0.10.0 needs no change.
- Two optional settings: `TOME_CMS_COUNTRY_HEADER` and `TOME_CMS_GEOIP_PATH`.

## Stats

Stats is the first entry under Content. It shows the views, reads and read ratio of every
article and page against the period of the same length before. It also shows a chart by day,
or by month over a year, where readers came from, and their devices, countries and languages.
Every choice is in the address.

- A view counts once per page per browser tab. A read counts when the end of the article comes
  into view and the tab has been visible for 15 seconds in all, again once per tab. The read
  ratio is reads over views. It changes in points, never as a percentage of a percentage.
- TomeCMS counts into daily totals, with no cookie and no outside service. It keeps no record of
  any reader, only the referring host, never the address.
- These are not counted:
  - the owner's own browser, once it has opened the admin
  - readers who set Do Not Track or Global Privacy Control
  - fetchers that call themselves bots
  - theme previews, and pages that are not an article, a page or the home page
- Countries come from a CDN's `CF-IPCountry` header when there is one, else from DB-IP Lite, else
  "Unknown". A server-built image has no database until `dbip-country-lite.mmdb` is put in
  `data/geoip/` and TomeCMS is restarted. The address is used for that lookup and for the limit,
  in memory, and never stored.
- An article's own screen links to editing it, and to the site while it is published there. A
  deleted article keeps its numbers and is listed as deleted.
- The numbers are estimates. Someone determined can add to them, up to 120 hits in ten minutes
  from one address, or from one IPv6 /64. Behind a reverse proxy, the reader's address is the
  last `X-Forwarded-For` entry, and it is believed only from a loopback or private address. With
  a CDN in front, the README shows how to pass the reader's own address.
- Counting starts with this version and cannot reach back.

## Maintenance

Maintenance sits under Settings. It closes the site to visitors while the owner works on it.

- Visitors get a 503 page in their language. It is built from one of four templates, Minimal,
  Logo, Picture and Countdown, with the owner's heading, message, picture and return time. With
  a return time, the answer carries `Retry-After`.
- The feeds and `/api/v1/content/*` answer 503 too. The API's answer carries the owner's words,
  so a headless site can draw its own page.
- The admin, sign-in, health checks, media and the owner's previews stay open. The owner still
  sees the site while signed in, under a bar that says visitors do not.
- The page is saved apart from the switch. The site closes and opens with a switch, never on
  unsaved words, and never reopens by itself.
- A picture the maintenance page uses cannot be deleted from the library. The refusal names
  the page.

## Popup

Popup is a plugin: a box over the public site.

- It holds a picture, a heading, a few words, and a button that links to a page or an https
  address. It also has a way to decline, and small print, in Thai and English.
- It opens after 5, 10 or 20 seconds, or as the reader leaves, on every page or on the home page
  only. It never opens over another dialog, and once closed it does not open again until its
  content changes.
- The core checks what the plugin returns before drawing it: a link that is not the site's own
  or https is dropped, and the picture must be a ready image from the library.

## paper

`paper` can show the author's links under an article as icons, or as icons and words. GitHub,
X, LinkedIn, Facebook, Instagram and YouTube are drawn as their own marks, told by the link's
address, and any other link gets a plain one. Words stay the default.

## The admin

Settings in the admin's menu folds out to General and Maintenance, the way Appearance holds
Themes and Plugins.

## For theme authors, plugin authors and headless sites

- A theme draws nothing new for Stats. The core adds the counting script. A read is measured
  from the end of the first `<article>` on a post or page, so keep the article's own `<article>`
  first there, as `paper` and `plain` do.
- Plugins gain a `choice` setting (with `options`) and an `image` setting chosen from the
  library. They also gain `previewHref`, and the `sitePopup` half of the `publicPage` hook. The
  library refuses to delete a picture a plugin setting holds.
- `POST /api/v1/stats/hit` counts a view or a read and answers `204` either way. In headless
  mode it accepts any origin with `Content-Type: application/json`; the README shows the call.
  While the site is closed, `/api/v1/content/*` answers 503 with a `maintenance` object. The
  OpenAPI document describes both.

## Validation boundary

- 530 unit tests, `astro check` with no error and no warning, and the production build.
- Integration tests against a real PostgreSQL:
  - the stats table's checks
  - 200 hits at once making exactly 200
  - every reason a hit is dropped
  - the Stats screen's queries for each range, filter, top ten and page
  - the maintenance settings and their closed-site answers
  - the popup's settings, pictures and public checks
- The maintenance, public-plugins and Stats browser specs, on both the desktop and the phone
  projects. The Stats spec reads a view, a read earned with a paused clock, the owner's browser,
  Do Not Track and Global Privacy Control. It also opens the screen with seeded numbers and
  checks nothing overflows at 375 pixels.
- `npm audit --omit=dev` reports no advisory at all.
- Each guard added along the way was checked by putting back the bug it guards against.

What is required before a production tag is unchanged from the
[0.3.0 notes](0.3.0.md#still-required-before-a-production-tag).
