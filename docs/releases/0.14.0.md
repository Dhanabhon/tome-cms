# TomeCMS 0.14.0

Date: 2026-09-27
Status: Release candidate; tagged and published as a GitHub release, not for production

TomeCMS 0.14.0 is 0.13.0 with two tools for a new server: a script that prepares Ubuntu 24.04
for TomeCMS, and a cloud-init file that prepares a server and installs TomeCMS on its first
boot. Nothing in the application changed.

This is still a pre-1.0 release candidate. A 0.x site upgrades in place when the deploy helper
is run again from a newer checkout.

## Upgrading

There is no migration, no new setting and no new runtime dependency. A site on 0.13.0 or
0.12.1 reads "TomeCMS 0.14.0 is available." under "System" once this release is published.

An installation created from a version earlier than 0.11.0 still needs what the
[0.11.0 notes](0.11.0.md#upgrading) list.

## Preparing a new server

`scripts/prepare-vps.sh` runs as root on Ubuntu 24.04, `amd64` or `arm64`, and sets up what
the deploy helper needs:

- Docker Engine with its Compose plugin, from Docker's apt repository
- Node.js 22 from NodeSource, at `/usr/bin/node`, where the managed install from 1.0.0 needs it
- the GitHub CLI from GitHub's apt repository, recent enough for the managed install to check
  attestations with it
- a swap file on a server with less than 4 GB of memory
- `ufw` with SSH allowed first, on every port the SSH server listens on, then 80 and 443
- Caddy as the reverse proxy for the two origins, with the `Host` header passed on and a
  25 MB body limit on the media origin, and certificates Caddy gets by itself

It checks the server before it changes anything, lists every problem it finds, and stops.
`--dry-run` prints each step and changes nothing. `--no-firewall` and `--no-proxy` leave those
two alone. Running it again is safe: each step says whether it changed something or found it
done, and an apt source for Docker, NodeSource, GitHub or Caddy set up some other way is kept.

`deploy/cloud-init.yaml` is user data for a new server. The owner fills in the two addresses.
On the first boot the server runs the script, creates a `tomecms` account, and runs the deploy
helper. The login message then says where to finish the install and how to read the
installation token. The file holds no secret, the install log is readable by root only, and
`sudo /usr/local/sbin/tomecms-first-boot` runs the install again if it did not finish.

[Preparing a new server](https://dhanabhon.github.io/tome-cms/start/prepare-server/) on the
documentation site describes both, in English and Thai.

## For theme authors, plugin authors and headless sites

Nothing a theme, plugin or headless site depends on changed.

## Releasing

A release now also sets `TOMECMS_VERSION` in `deploy/cloud-init.yaml` to its own tag. A unit
test fails until it does.

## Validation boundary

- `npm run check` passes, and `shellcheck` reports nothing on the script or on the first-boot
  script inside the cloud-init file.
- `npm run test:unit`: 584 tests, all passing.
- CI runs the script with `--dry-run` as root on its Ubuntu 24.04 runner, which has systemd,
  and the dry run passes every check there.
- In an `ubuntu:24.04` container on `arm64`, the script installed Docker, Compose, Node.js 22,
  the GitHub CLI and Caddy for real, and a second run found every step done. It moved a
  NodeSource Node.js 20 to 22, kept a Caddy apt source set up by Caddy's own instructions, and
  opened both ports of an SSH server listening on two. The first-boot script stopped with the
  right message on the example addresses and on a release without the script, and ran through
  the whole preparation on a test tag before the deploy helper stopped for want of a Docker
  daemon, which a container does not have.

Neither tool has been run on a real server. The firewall, systemd, a deploy that finishes, and
the first boot of a 1.x release were not exercised. That belongs with the acceptance on the two
real HTTPS servers, `linux/amd64` and `linux/arm64`, that the
[road to 1.0.0](../plans/2026-09-24-road-to-1.0.0.md) names, still to be done before 1.0.0.
What is required before a production tag is unchanged from the
[0.3.0 notes](0.3.0.md#still-required-before-a-production-tag).
