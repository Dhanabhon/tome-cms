# TomeCMS 1.1.0

Date: 2026-09-29
Status: Stable release; tagged and published as a GitHub release

TomeCMS 1.1.0 is the first feature release after 1.0. The editor gains text colour, underline,
strikethrough and numbered lists, and the file library's folder menus behave. Every 1.0.x
feature keeps working, and `/api/v1` is unchanged.

## Upgrading

- **A managed install** updates from "System" in the admin, as
  [Updating](https://dhanabhon.github.io/tome-cms/running/updating/) describes. There is no
  migration, no new setting and no new runtime dependency.
- **A build from source** upgrades in place by running the deploy helper again.
- **A headless site** that draws `contentHtml` itself should add CSS for the six text-colour
  classes below. It is not required: without it, coloured words keep the colour of the text
  around them.

`deploy/cloud-init.yaml` now installs 1.1.0.

## The editor

- **Text colour.** A new "Text colour" button on the formatting bar opens a row of swatches:
  Default, Red, Orange, Green, Blue, Purple and Grey. A colour is stored by its name, as
  `<span class="tome-color-red">`, never as a value, and a name outside the six is dropped from
  the stored document. Each name has one shade for light mode and another for dark mode, so
  coloured words stay readable on a dark screen. Every shade holds at least 4.5:1 against both
  page surfaces in its mode, and the contrast test pins that. Green sits at a hue clear of the
  link colour, so it does not read as a link.
- **Underline and strikethrough.** New "Underline" and "Strikethrough" buttons on the bar, with
  Ctrl+U (⌘U) and Ctrl+Shift+S (⌘⇧S). Underline had been switched off because the sanitizer
  dropped `<u>`; both now allow it.
- **Numbered lists.** "Numbered list" joins "Bullet list" in the `+` menu and the `/` menu.
  Strikethrough and numbered lists were already in the schema and only lacked a control.
- **The bar keeps the cursor.** A button on the formatting bar kept the focus it took, so the
  words typed after pressing Bold, Italic or any other went nowhere. The bar now leaves the
  focus in the editor, as the `/` menu does.

## The file library

Two folder menus could be open at once and overlap, a press elsewhere left them open, and the
focus ring on the "..." circled past the edge of its pill. Only one folder menu opens at a time
now, a press outside closes it, Escape closes it and returns focus, the ring stays inside the
pill, and the open tint is lighter.

## For theme authors, plugin authors and headless sites

- A post's `contentHtml` may now hold `<u>` and `<span class="tome-color-…">` with one of
  `tome-color-red`, `-orange`, `-green`, `-blue`, `-purple` or `-grey`. The bundled themes get
  their shades from `--color-text-red` and its five siblings in `installer-tokens.css`, which a
  theme can override. `DESIGN.md` lists the values.
- Nothing was removed or renamed, so an existing theme, plugin or headless site keeps working.
  [The API page](https://dhanabhon.github.io/tome-cms/api/overview/) describes the classes.

## Validation boundary

- `npm run check` passes, and the documentation site's check and build pass.
- `npm run test:unit`: 602 tests, all passing, among them the sanitizer and server rendering of
  the new marks, the palette's contrast in both modes, and the folder menu wiring.
- CI's browser tests pass on both feature commits, including a new one that applies a colour,
  an underline and a strikethrough from the bar, checks the editor keeps focus after each, and
  makes a numbered list from `/`.
- In a real signed-in admin on a disposable database: the four tools, publish, and the public
  page in light mode (red as `oklch(0.52 0.18 25)`) and dark mode (`oklch(0.76 0.13 25)`); and
  the folder menu at 1440 and 375 pixels wide, measured before and after the fix (two menus open
  and the ring outside the pill, then one and inside).
- Not yet run on the managed server: updating it to 1.1.0 and using the new tools there is
  their first run on real hardware.
