# TomeCMS 1.11.0

Date: 2026-10-03
Status: Stable release; tagged and published as a GitHub release

TomeCMS 1.11.0 brings two things:
- **Almanac,** a third theme. It is warm and literary, with serif headings, soft paper colours and
  a grid of post cards.
- **`tome`,** a short command for looking after the server: `tome status`, `logs`, `backup`,
  `update` and `prune`.

The updater it comes with is 1.5.0. `/api/v1` is unchanged.

## Upgrading

1. **Update the application** to 1.11.0 from "System" in the admin, as
   [Updating](https://dhanabhon.github.io/tome-cms/running/updating/) describes. There is no
   migration, so the updater backs up the database alone.
2. **Then, on the server,** upgrade the updater, which also installs `tome`. Run these from a
   checkout of `v1.11.0`, after `npm ci`:

   ```sh
   sudo npm run updater:upgrade -- --dry-run
   sudo npm run updater:upgrade
   ```

   Update the application first: an application before 1.10.0 cannot read every message the newer
   updater can send.

A build from source upgrades in place by running the deploy helper again. `deploy/cloud-init.yaml`
now installs 1.11.0.

## Almanac

Choose it under Appearance → Themes.

**Look.**
- Headings are set in Trirong, a serif with Thai and Latin. The body is in IBM Plex Sans Thai.
- The palette is warm paper, ink and a moss-green accent, with light and dark versions. Contrast is
  checked in both.

**The home page.**
- A hero band: a headline, a lead line and two buttons.
- A row of category pills with a search field, as in Paper.
- A grid of post cards: 3 columns on a wide screen, 2 on a tablet, 1 on a phone.
- **A card's top panel:**
  - it shows the post's cover;
  - with no cover, it shows one of six calm tones, always the same for a category, with the
    category's first letter.
- "More posts" loads the next set.

**Posts and pages.**
- A reading column with the category, a large title, the lead and the meta line.
- The cover image, then the body.
- "More in {category} →" at the end of a post.
- A thin reading progress bar at the top, which you can switch off.
- Headings inside a post or page are styled in the same serif.

**Settings.**
- The hero: on or off, its headline, lead, and each button's label and link.
- The reading progress bar: on or off.
- Every setting falls back to a sensible default when left empty:

  | Setting | Default |
  |---|---|
  | headline | the site name |
  | lead | the tagline |
  | first button | "Start reading", which opens the newest post |
  | second button | "All posts" |

- A button link must be a path on the site or an `https://` address. Any other link drops its
  button.

**Header and footer.**
- The header carries the menu, including sub-menus, the language switch and the theme switch.
- On a phone the language switch shrinks, so the site's name stays whole.

**Notes for theme authors.**
- Each post a theme's home page receives may now carry its `categories`
  (`ThemeHomePost`). The field is optional, and adds no data.
- An h1 inside a post or page body is demoted to h2 in all three themes, aligned headings included.
  The page keeps one h1.

## `tome`

**Installing it.** `sudo npm run updater:upgrade` installs the command as `/usr/local/bin/tome`.
Run it with `sudo`.

| Command | What it does |
|---|---|
| `tome status` | the versions, whether the site is ready, the containers, the free disk, the last update and the newest backup |
| `tome logs [app\|postgres\|seaweedfs\|updater] [-n N] [-f]` | the logs, with secrets hidden |
| `tome backup [--full] [--yes]` | takes a backup now; the site is in maintenance while it runs and always comes back |
| `tome update [version] [--yes]` | installs the newest release, or a named one, through the updater, with the same checks, backup and rollback as "System"; the server needs no passkey, because `sudo` already means full control |
| `tome prune [--yes]` | lists, then removes, old application images; it keeps the running one and the one before it |

Exit codes: 0 for success, 1 for a failure or refusal, 2 for wrong usage.

## Updater 1.5.0

**New on its socket:**
- `/v1/backup` (take a backup, and follow it);
- `/v1/prune`, with a dry run;
- `/v1/busy`.

Updates, backups and prunes share one lock, so they never overlap.

**For applications already installed,** `/v1/status` and the update record are unchanged, so they
read the updater exactly as before.

**Backups on request:**
- they are refused when the disk is below the minimum;
- a backup that fails still starts the site again;
- an updater that restarts mid-backup never stops a site that is already running.

**Fixed:** names ending in `_KEY_ID` (such as `S3_ACCESS_KEY_ID`) are identifiers, not secrets. The
updater's and the installer's failure diagnostics were always hidden on a default install, because
that short value counted as a secret. They now show.

## Testing

- **Unit:** about 1,100 tests, including:
  - Almanac's settings, tones and CSS after the production minifier;
  - the CLI's commands, against fixtures built like a real server;
  - backups and prunes on request, including a failed final write and an updater restarting
    mid-backup;
  - an older application's view of `/v1/status`.
- **Managed update harness:**
  - `tome status`, `tome prune --dry-run` and `tome backup` with the site ready afterwards;
  - the shim installed by `updater:upgrade`.
- **Browser:**
  - Almanac's pages, settings and edge cases: Thai categories, no posts, no tagline, long titles
    and an empty search;
  - its header on a phone;
  - keyboard and reduced motion;
  - Paper and Plain unchanged.
