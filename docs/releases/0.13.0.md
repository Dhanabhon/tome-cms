# TomeCMS 0.13.0

Date: 2026-09-27
Status: Release candidate; tagged and published as a GitHub release, not for production

TomeCMS 0.13.0 is 0.12.1 with the admin's words made plainer and consistent in English and
Thai, two small additions to the admin that the owner chose, and a release process that runs
itself from a merge into `main`.

This is still a pre-1.0 release candidate. A 0.x site upgrades in place when the deploy helper
is run again from a newer checkout.

## Upgrading

There is no migration, no new setting and no new runtime dependency. A site on 0.12.1 reads
"TomeCMS 0.13.0 is available." under "System" once this release is published.

An installation created from a version earlier than 0.11.0 still needs what the
[0.11.0 notes](0.11.0.md#upgrading) list.

## The admin's words

A review of every admin string found 41 places where the words were unclear, inconsistent, or
not natural Thai. Each one was fixed in both languages, along with the documentation that quotes
them and every screenshot.

- One word for each thing:
  - passkey, in lower case unless it starts a label
  - File Manager / คลังไฟล์
  - post / บทความ, and เพจ for a page in Thai (หน้า now means a screen or the home page only)
  - image / ภาพ, redirect / เปลี่ยนเส้นทาง, ผู้เข้าชม for a visitor, and เว็บไซต์ in sentences
  - ลบ for Delete and เอาออก for Remove
  - แนะนำ for a suggestion
- Developer words are gone from the screens an owner uses. Slug became URL name, Meta title
  and Meta description became Search title and Search description, and MenuBar became Header
  menu. "answers 404", "relative URL", and a theme that "draws your site" are said plainly.
- The System screen says what an owner can do. The update mode reads "Notify only", not
  `check-only`. The install confirmation is in the admin's language. The banner for a database
  that needs updating starts with what fails.
- Every error says what happened and what to do next. Every empty screen says how to start.
- A delete confirmation names the language edition ("the English edition"), not a locale
  code.
- The Settings, Plugins, Profile and Themes screens, and the installer's Thai, had English
  text left in them. Those now use the admin's copy too.
- No sentence has an em dash or an en dash. Thai asks without กรุณา or โปรด, in the admin's
  plain voice.

## Two additions

- **Profile links are named from a list.** Each link's name is chosen from GitHub, X,
  LinkedIn, Facebook, Instagram, YouTube and Website, or "Other…" with a name of your own. A
  link saved under any other name opens as "Other…" with that name. What is stored is still a
  name and an address, and a theme still picks a link's mark from its address.
- **The admin has a footer.** Every admin page ends with "Thanks for writing with TomeCMS.",
  with TomeCMS linking to the documentation, and "Made by TOMERA Co., Ltd." with the version
  the server runs.

Both are small. The freeze on new features before 1.0.0 still holds for everything else.

## Releasing

Work now happens on the `develop` branch, and `main` holds released code.

A merge into `main` that carries a version with no tag yet releases itself:
1. Once CI passes on the merge, `tag-release.yml` tags the commit `vX.Y.Z`.
2. It then starts `release.yml` on that tag. The attestations still come from `refs/tags/vX.Y.Z`,
   which is what the installer and the updater require.

A merge that keeps the version releases nothing. A new version with no notes file in
`docs/releases/` stops before it is tagged. CI and the documentation build also run on pushes
to `develop`, and a browser test that fails in CI now leaves its trace as a downloadable
artifact.

## For theme authors, plugin authors and headless sites

Nothing a theme, plugin or headless site depends on changed. The public API and the content
it serves are the same as in 0.12.1.

## Validation boundary

- `npm run check`: `astro check` with no error and no warning, and the scripts' self-tests.
- `npm run test:unit`: 569 tests, all passing.
- `npm run test:e2e`: the full run on the copy branch passed 91, skipped 44 (the specs that run
  on the desktop project only) and failed 3. Two failures passed on a lone rerun: the known
  editor flakes. The third was a Stats test still asserting the old dash; it was fixed and
  passed. The specs touched by the last copy fixes, Stats and the installer, pass on the
  release tree. CI on `develop` passed in full.
- The documentation site: `npm --prefix website run check` found every page's twin and no
  listed mark, and all 30 screenshots were taken again and read.

0.13.0 has not yet been installed on the two real HTTPS servers, `linux/amd64` and
`linux/arm64`, that the [road to 1.0.0](../plans/2026-09-24-road-to-1.0.0.md) names. That is
still to be done before 1.0.0. What is required before a production tag is unchanged from the
[0.3.0 notes](0.3.0.md#still-required-before-a-production-tag).
