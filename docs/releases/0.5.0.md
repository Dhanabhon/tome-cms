# TomeCMS 0.5.0

Date: 2026-09-21
Status: Release candidate; not tagged for production

TomeCMS 0.5.0 is 0.4.0 with one more suggestion, a button that no longer claims work it is
not doing, and workflows that run on the Node GitHub still supports. This is still a pre-1.0
clean-install line; the 0.2.0 release gates remain open.

## Upgrading

Nothing to migrate: no migration landed after 0.4.0, so an installation created from that
candidate starts as it is. One created from 0.3.0 needs what the
[0.4.0 notes](0.4.0.md#upgrading) list, and one from before that the
[0.3.0 notes](0.3.0.md#upgrading) as well.

## For plugin authors

Nothing a 0.4.0 plugin relied on was taken away.

- `editorSuggestions` has a third method beside `categoryLikelihoods` and `pickExcerpt`:
  `pickDescription`, which of the passages the core found best sums an article up for someone
  who found it in a search. It takes and returns what `pickExcerpt` does, and the core keeps
  its answer on the same condition -- one of the passages it offered, or nothing. It is a
  method of its own rather than a flag on `pickExcerpt`, so a plugin that only knows how to
  pick a card's line is never asked for a summary it would answer with a teaser.

## Highlights

### A description from the article

- The settings drawers of a post and a page offer a passage from the article for its meta
  description: the summary under its title in a search result, and on a post's own page where
  the theme shows it, as `paper` does. It comes through the TypeSafe plugin, like the other
  suggestions, and only once an owner has switched that on.
- It is asked for differently from the excerpt. A card asks what an article is about; a search
  result is asked what it says, because someone searching wants to know whether it answers
  them before they open it.
- Its passages run to 160 characters -- what a search result shows, and what the description is
  already cut to when it is left blank. The field holds 320, but a summary cut off mid-sentence
  in a result is not one. An excerpt's passages stay at 120.
- As with the excerpt, nothing is applied: the suggestion is a quotation with its own button,
  and the words are the owner's, as written.

### The admin

- Publish and Update spin for their own press and nothing else. The button took its busy state
  from the editor's saving, which the autosave shares, so every autosave put a spinner on
  Update while the owner typed -- reading as a publish nobody asked for, on a button that
  stayed clickable under a waiting cursor. An autosave is shown where it always was, in the
  save state beside the button.

### Operations

- Every action the workflows use runs on Node 24. GitHub has deprecated Node 20 for actions and
  was already forcing `actions/setup-node` onto 24, and said so on the 0.4.0 run. The release
  workflow, which has never run, pinned four Docker actions to majors on Node 20 as well, and
  would have met the same deprecation on the day of the first tagged release. Each moved to its
  current major, pinned by commit, once it was checked that every input these workflows pass
  still exists and that the image build still returns the digest the attestation reads.
- The release workflow sets up Node 22, the version CI tests and the image runs. It had built
  with whatever Node the runner image carried that day.
- Both workflows run on `ubuntu-24.04` rather than `ubuntu-latest`, which becomes Ubuntu 26 from
  19 October 2026. The browser tests install Chromium's system libraries with `--with-deps`,
  which knows a fixed list of distributions, and a new one can arrive before the Playwright
  that supports it. Moving forward should be a commit of its own, able to fail on its own.

## Validation boundary

The same gates as 0.4.0, green on the commits this release contains and with no warnings left
on the runs. One path had nothing covering it: the server asking a plugin for a suggestion
through the owner's stored settings. It has an integration test now. The browser tests answer
suggestions in the browser, so they could not have noticed the card's question being asked
for the description. Each new guard was checked by putting back the bug it guards against.

The release workflow's changes can be exercised only by tagging a release, which publishes an
image; they were checked against each action's own declaration instead.

What is still required before a production tag is unchanged from the
[0.3.0 notes](0.3.0.md#still-required-before-a-production-tag).
