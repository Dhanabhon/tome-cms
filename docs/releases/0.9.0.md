# TomeCMS 0.9.0

Date: 2026-09-23
Status: Release candidate; not tagged for production

TomeCMS 0.9.0 is 0.8.0 with the editor moved off `novel` and onto Tiptap 3, and with the
library's last rough edges from 0.8.0 filed down. Nothing a writer stores changed: a post
saved before this release opens, renders and saves exactly as it did. This is still a pre-1.0
clean-install line; the 0.2.0 release gates remain open.

## Upgrading

No migration. `npm run db:migrate` has nothing to do for this release, and an installation
created from 0.8.0 starts as it is. An installation created from an earlier version still
needs what the [0.8.0 notes](0.8.0.md#upgrading) list.

- A theme, a plugin or an API client written for 0.8.0 needs no change. The editor is an admin
  screen; what it produces and what the site renders are unchanged.
- A site that forked or patched anything under `src/components/admin/` has more to merge than
  usual: the editor's components were rewired, and `SlashCommands.tsx` moved to
  `src/components/admin/editor/slash-items.tsx`.

## The editor, without novel

`novel` was the package the admin reached Tiptap through. It had had no release since January
2025, it pinned the editor to Tiptap 2, and it brought eight libraries the admin never loaded:
`cmdk`, `tippy.js`, `jotai`, `tunnel-rat`, `react-markdown`, `react-tweet`, `react-moveable`
and `katex`. All nine are gone, and what they did is now about three hundred lines in
`src/components/admin/editor/`.

- The `/` menu is ours, over Tiptap's own suggestion plugin, which anchors it to the cursor and
  follows it. Up, Down, Home, End, Enter and Escape all do what they did; a pointer hovering an
  item highlights it, as before.
- The formatting bar and the table's bar come from Tiptap's menus, placed by Floating UI where
  tippy used to place them. The table's bar still sits over the table's top left corner rather
  than over the words, so it stays put as the cursor moves from cell to cell.
- An image dropped or pasted into the page keeps its own upload: the picture appears at half
  opacity where it will land, and the alert still says why a file was refused, in the owner's
  language.

Three bugs came with the code `novel` used to hold, and are fixed rather than carried:

- A quick upload could answer before the picture had been read from disk. The picture was then
  thrown away and a placeholder stayed in the article for good. The picture goes in first now,
  and the upload starts after it.
- A failed upload used to leave a writer's chosen words deleted with nothing in their place.
  Nothing is deleted any more: a picture pasted over chosen words lands at the start of them
  and leaves them alone.
- Leaving the page while an upload was in flight threw. Every answer now checks the editor is
  still there.

One thing Tiptap 3 offers was deliberately turned off. Its starter kit appends an empty
paragraph after any document that does not end in one, which would have quietly added a
paragraph to every post that ends in a quote, a table, a code block or a file card. Adopting it
is a decision about what a post stores, not a side effect of an upgrade, so it stays off for
now.

## The library

- A link to a folder that no longer exists opens All, where before it opened an empty view that
  read as if the files were gone.
- Alternative text sent with a document is refused as a bad request, where it used to fail as a
  server error.
- A card whose file has left the library says to choose a file from this site, rather than
  calling the article invalid.
- A document is checked from one object: both of its reads carry `If-Match`, so a file replaced
  while it is being checked is refused instead of half-accepted.
- On a phone, the library's type and folder selects are captioned.

## For theme authors and headless sites

Nothing changed. `contentHtml`, `contentJson`, the public API, the OpenAPI document and every
theme hook are what 0.8.0 left them. The editor's own schema is unchanged node for node and
mark for mark, and the server renders stored documents through the same second schema it always
did.

## Validation boundary

- 484 unit tests, `astro check` with no error and no warning, and the production build.
- The browser suite, run whole, with the phone project's Chromium-only tests skipped as by
  design. The thirteen tests that cover the writing surface were the gate for this work, and
  two of them earned their keep: one caught the empty paragraph the starter kit would have
  added, and one caught the `+` button losing the box it measures itself against.
- `npm audit --omit=dev` reports no advisory at all. The forty-two moderate ones 0.8.0 lived
  with were every 2.x release of `@tiptap/core` against one advisory whose fix 2.27.3 already
  carried, and leaving the 2.x line ends the noise.
- Each guard added along the way was checked by putting back the bug it guards against.

What is required before a production tag is unchanged from the
[0.3.0 notes](0.3.0.md#still-required-before-a-production-tag).
