# TomeCMS 1.6.0

Date: 2026-10-01
Status: Stable release; tagged and published as a GitHub release

TomeCMS 1.6.0 gives code blocks a language, with highlighting in the editor and on the page, and lets
the owner turn a Markdown file into a draft post. `/api/v1` is unchanged.

## Upgrading

- **A managed install** updates from "System" in the admin, as
  [Updating](https://dhanabhon.github.io/tome-cms/running/updating/) describes. There is no
  migration and no new setting, so the updater backs up the database alone.
- **A build from source** upgrades in place by running the deploy helper again. `npm run build` now
  also bundles the Markdown reader's worker (`dist/server/markdown-parse-worker.mjs`); the deploy
  helper, the image and CI all run it.
- New runtime dependencies: `lowlight` and `highlight.js` (24 grammars only), `@tiptap/markdown`,
  `marked` and `yaml`.

`deploy/cloud-init.yaml` now installs 1.6.0.

## Code blocks

A code block has a language, chosen from the corner of the block: None, Auto, or one of 24 — Bash, C,
C++, C#, CSS, Dart, Diff, Go, GraphQL, TOML/INI, Java, JavaScript, JSON, Kotlin, Markdown, PHP,
Python, Ruby, Rust, SQL, Swift, TypeScript, HTML/XML and YAML. Auto names what it recognises, as in
"Auto (TypeScript)", and leaves a block it is unsure of plain. Typing ```` ```ts ```` and a space
starts a TypeScript block; the usual short names (js, py, sh, yml, …) are understood.

The editor colours the code as it is written. The published page is coloured on the server when the
post is saved, so a reader downloads no highlighting script. On the page a block is a light box with
its language in the corner (dark in dark mode), in both themes; a block with no language is plain.
The colours are new tokens (`--color-code-*`), each held to 4.5:1 against its background in both
themes. Very long code is shown plain past a budget, so a save stays quick.

## Importing a post from Markdown

"Import Markdown" on Posts turns one `.md` file into one draft:

- **What comes in:** the title, and from frontmatter the language, URL name, excerpt, search fields,
  categories that already exist, and a cover. Headings, lists, quotes, tables, links, code blocks
  (with their language) and `---` breaks come in as the editor's own blocks. It is always a draft,
  whatever the file says.
- **Pictures:** the sheet lists every picture the file names; choose the picture files, several at
  once, and each is matched to the post by its file name, or skip it. A picture from another site is
  kept as it is; one that cannot be used is left out, and a skipped picture leaves a line saying so in
  the post. A file used twice is uploaded once.
- **What is left out, and said:** HTML in the file, links that are not web or mail addresses,
  checkboxes in a task list, and categories that do not exist yet. The sheet ends with what happened
  and a link to the draft.
- **Bounds:** a file is at most 900 KB and 500 pictures, and is read in a separate worker with a time
  and memory limit, one at a time; a file too big, too complex or too long to store is refused before
  anything is uploaded, with what to do about it. A URL name already taken gets a short suffix.

## The editor

A post or page too long to store is refused with that reason instead of a generic error, measured the
way the database stores it.

## Testing

- Code blocks: languages and aliases, server highlighting (chosen, Auto, None), escaping of HTML in
  code, the sanitizer's allowlists, the contrast of every syntax colour, and an editor-to-page e2e.
- Markdown import: the parse (frontmatter, Thai, CRLF and BOM, the spike's clean-ups), the limits on
  adversarial files, the worker's time and memory limits against the built output, the routes (auth,
  origin, 413 and 429), sizes as Postgres measures them, and the sheet end to end.
