# TomeCMS 1.5.1

Date: 2026-09-30
Status: Stable release; tagged and published as a GitHub release

TomeCMS 1.5.1 gives the Plain theme a wide frame led by the newest post, sets Paper's header on cream
over a white page, and fixes a handful of admin fields and messages. `/api/v1` is unchanged.

## Upgrading

- **A managed install** updates from "System" in the admin, as
  [Updating](https://dhanabhon.github.io/tome-cms/running/updating/) describes. There is no
  migration, no new setting and no new runtime dependency, so the updater backs up the database alone.
- **A build from source** upgrades in place by running the deploy helper again.

`deploy/cloud-init.yaml` now installs 1.5.1.

## Plain

Plain no longer keeps everything in a 44rem strip. Its header, home page and footer span the same 80rem
frame as Paper, and it is still the system font with rules in place of surfaces, and no pictures on the
home page.

- **Categories and search on one row.** The categories are tabs (the one you are on is set in ink with a
  2px green line under it) and search sits at the end of the row as one field with the magnifier as its
  button. On a phone the search comes first, above the tabs, in sight and in tab order.
- **The newest post leads.** On the first page of a list without a search, the newest post runs across
  the width in a large title with its excerpt; the rest sit three to a row on a wide screen, two on a
  tablet and one on a phone, their excerpts cut at three lines. That first page holds seven posts, so the
  grid under the lead ends on a full row; the pages after it are the usual six and neither repeat nor
  skip a post.
- **The footer** sets the TomeCMS credit at the right, under the copyright on a phone.
- An opened article keeps its 44rem reading column, and its title now carries the lead's weight.

## Paper

Paper's header sits on cream (`--color-paper-2`) with its rule below, and the page, the text hero and
the footer are white (`--color-paper`), as the admin sets its navigation and its content. Dark mode
follows the same pair.

## The admin

- **A field turns red only when the admin says what is wrong.** The browser's own "this required field
  is empty" state no longer colours admin fields, so a field that clears after a save, such as the File
  Manager's folder name, no longer stays red.
- **Empty names are told why.** An empty folder name, new or renamed, says so beside the field, which
  takes the focus; Navigation's add dialog and Categories mark and focus the field an empty submit is
  about.
- **Security's name warning** goes as soon as a name is typed.
- **A failed upload says what the server said.** The upload dialog and the library show the server's own
  message where the admin has no words of its own for it, and never the browser's raw text; anything else
  is still "The File Manager is temporarily unavailable".

### For theme authors

`ThemeManifest` gains an optional `leadsFirstPage`. A theme that sets its newest post apart from its grid
sets it, and the home route then asks an unsearched first page for one more post than the page size;
cursors stay tied to the page size. A theme that does not set it is unchanged.

## Testing

- `tests/unit/plain-theme.test.ts` and `tests/unit/theme-page-size.test.ts` cover Plain's frame, lead
  and page size; `tests/e2e/home-search.spec.ts` checks that page 2 follows a seven-post first page
  without a repeat or a gap.
- `tests/unit/admin-surface-tokens.test.ts` fails on a `:user-invalid` rule in an admin stylesheet, and
  its form and picker guards now read the folders rather than git's index.
