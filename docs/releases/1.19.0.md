# TomeCMS 1.19.0

Date: 2026-10-06
Status: Stable release; tagged and published as a GitHub release

TomeCMS 1.19.0 makes the site look better where it is found and shared: a share image for links
to pages without a cover, a breadcrumb for search results, and a site description in each
language. The documentation's pictures of the admin are all new. `/api/v1` is unchanged.

## Upgrading

- **A managed install** updates from "System" in the admin, as
  [Updating](https://dhanabhon.github.io/tome-cms/running/updating/) describes, or with
  `sudo tome update` on the server. This release has one migration,
  `032_share_image_and_descriptions`, so the updater takes a full backup (database and media)
  before it applies it.
- **A build from source** upgrades in place by running the deploy helper again; it runs the
  migration.
- **The updater** stays at 1.6.0. Nothing to upgrade on the server.
- **A proxy of your own** must let the CMS origin take a request body of at least 8 MB, for the
  share image. The Caddy that `prepare-vps.sh` writes has no such limit.
- **An admin tab left open** from before the update cannot save Settings (it sends the old
  description field). Reload it.

`deploy/cloud-init.yaml` now installs 1.19.0.

## Added

- **Share image.** Settings → site identity has a fourth image, "Share image". When a page
  without its own cover is shared on LINE, Facebook or X, the card shows it. TomeCMS crops it to
  1200 × 630, saves it as a JPEG without its metadata, and lays a transparent image on white. It
  takes JPEG, PNG or WebP up to 8 MB; not SVG, which those apps do not draw. A post's own cover
  still comes first.
- **Breadcrumbs for search results.** Every post and page carries a `BreadcrumbList` (the
  language's home, then the page), so a search result can show the site's name and a path
  instead of a bare address. Like the rest of the structured data, it is left out while the site
  is kept out of search results.
- **A site description in each language.** Settings has a Thai and an English description in
  place of one. Each language's home page, and the description search engines and shared links
  read, uses its own; an empty one borrows the other language's. The existing description moves
  into the site's default language when you update.
  - `/api/v1` and MCP keep their meaning: the default language's description. A site that fills
    only its second language's gets an empty description there.
  - If you go back to 1.18.x and change the description there, then update again, the two new
    fields keep the values they had; set them again in Settings.

## Fixed

- **Profile links.** Side by side, each link's "Remove" button sat a line below its fields.
  It now sits on their line, for a link from the list and for one with a name of its own.

## Changed

- **Every picture of the admin in the documentation is new**, in English and Thai, with
  descriptions to match. They had been taken before the admin's 1.4.0 redesign.

## Testing

- **Unit:** the share image is 1200 × 630, a JPEG without metadata, white where it was clear,
  never an SVG, and may weigh 8 MB while a logo may weigh 1 MB; the image a page shares, in order;
  the breadcrumb for a post and a page, none on the home page or when hidden from search; the
  description's fallback; the installer keeps its description in the site's language.
- **Integration:** a share image is stored, replaced and removed with nothing left behind, and a
  reset accounts for it; the migration moves a Thai site's description into its Thai field; both
  descriptions are saved and read back.
- **Browser:** each profile link's "Remove" sits on its fields' line; an SVG share image is refused and a photo is taken; a page without a cover and both
  home pages then share it at 1200 × 630; a page carries its breadcrumb and the home page none;
  each home page shows its own description.
- **Operations:** the managed update harness, with the migration.
