# TomeCMS 1.0.2

Date: 2026-09-28
Status: Stable release; tagged and published as a GitHub release

TomeCMS 1.0.2 makes uploads work on a managed install, says every update reason on the
"System" screen in the owner's language, and lets the server preparation and the install share
one clone. It is also the first release a managed install takes from the admin: `1.0.1 → 1.0.2`.

## Upgrading

- **A managed 1.0.1 install** updates from "System" in the admin, as
  [Updating](https://dhanabhon.github.io/tome-cms/running/updating/) describes. There is no
  migration, no new setting and no new runtime dependency.
- **A build from source** upgrades in place by running the deploy helper again.
- **A 0.x install** still needs a fresh server, as the [1.0.0 notes](1.0.0.md#upgrading) say.

`deploy/cloud-init.yaml` now installs 1.0.2.

## Uploads

On a managed 1.0.1 server, every file uploaded in the admin ended with "Storage verification is
temporarily unavailable. Try finalizing again." After the browser uploads a file, the server
checks it in the bucket with a `HEAD` request. Right after the upload, SeaweedFS 4.46 answered
that first `HEAD` with `403`, and every one from about 50 ms later with the file. The storage
client does not retry a `403`, so the check failed at once. The tests reach SeaweedFS directly
over HTTP, and never met that moment.

The check now tries up to four times, 200, 400 and 600 ms apart, on anything but a missing
file. When it still fails, and when reading an image back fails, the application's log names the
storage error and its status, such as `Upload verification failed: Unknown 403`, where it said
nothing before.

## The admin

On a managed install, the "Updates from the admin" card showed the updater's reason in
English, such as "No compatible update is available." on the Thai screen. The server now sends a
code with it, and the admin says each one in English or Thai. The English reason stays in the
API.

## Installing

- **One clone.** Preparing a new server now clones the release's tag into `/opt/tome-cms-src`,
  and the install runs from the same folder. `prepare-vps.sh` ends with only `cd` and `npm ci`
  and the install when it runs from a clone of the release tag.
- **No account needed as root.** Run by root, `prepare-vps.sh` no longer asks for an account.
  The managed install runs as root, and only a build from source needs an account in the
  `docker` group. `--create-user --user tomecms` still makes one, for logging in over SSH
  without root.

## The documentation

A new page, [Troubleshooting](https://dhanabhon.github.io/tome-cms/running/troubleshooting/),
lists the messages met while installing and running TomeCMS: missing addresses, busy ports, a
checkout off its tag, SSH's warning after a server is rebuilt, storage that does not answer, and
the upload message above, each with what it means and what to do. English and Thai.

## For theme authors, plugin authors and headless sites

Nothing a theme, plugin or headless site depends on changed. The admin API's update answer
gains `installability.code` beside the unchanged `reason`.

## Validation boundary

- `npm run check` passes, the documentation site's check and build pass, and `shellcheck`
  reports nothing on `scripts/prepare-vps.sh`.
- `npm run test:unit` passes, among them the tests for each update reason's words in both
  languages and for `prepare-vps.sh` run by root with no account.
- The media integration tests pass, among them a new case where storage answers the first
  `HEAD` with `403`: the upload finalizes, after two `HEAD` requests, and a `403` that lasts
  still answers `503`.
- The cause was found on a managed 1.0.1 server (DigitalOcean, `linux/amd64`): the same `HEAD`,
  `GET` and image checks passed when run minutes after the upload, and an upload made and
  checked at once got `403` on the first `HEAD` and succeeded on the next four.

The same server is the first acceptance row: a fresh managed 1.0.1 install, completed through
the wizard, with posts, pages, categories and menus created. Updating it to 1.0.2 from the
admin, and an upload after that, finish the row in the
[1.0.0 notes](1.0.0.md#acceptance-on-real-servers).
