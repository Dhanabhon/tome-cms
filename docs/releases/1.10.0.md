# TomeCMS 1.10.0

Date: 2026-10-02
Status: Stable release; tagged and published as a GitHub release

TomeCMS 1.10.0 brings header sub-menus. A header item can hold one level of items under it, and a
**group** is a label with no link that only opens them. The release also gives the managed updater
its own error for a full disk, and lets it remove the application images it replaced, after the
disk on the test server filled up during the 1.9.1 update.

`/api/v1/content/navigation` gains `children`. A group answers with `href: null`. See
[The API](#the-api).

## Upgrading

- **A managed install** updates from "System" in the admin, as
  [Updating](https://dhanabhon.github.io/tome-cms/running/updating/) describes. This release has
  one migration, `029_navigation_parent`, so the updater takes a full backup first.
- **A build from source** upgrades in place by running the deploy helper again, which runs the
  migration.
- **The updater** changes only through `sudo npm run updater:upgrade`. To get the new disk message
  and the image clean-up:
  1. update the application to 1.10.0 from "System" first;
  2. then, on the server, from a checkout of `v1.10.0` after `npm ci`, run
     `sudo npm run updater:upgrade`.

  That order matters: an application before 1.10.0 cannot read the new message. The updater refuses
  to send it to one, so the order is a precaution, not a trap.

`deploy/cloud-init.yaml` now installs 1.10.0.

## Sub-menus

**On the Navigation screen (Header only):**
- **Move under the item above** puts an item at the end of the nearest top-level item above it.
  **ย้ายออกจากเมนูย่อย / Move out** brings it back up.
- Moving a parent up, down or by dragging takes its items with it. A sub-item moves only among its
  siblings.
- **Group (no link)** in the add dialog makes a label that only opens its sub-menu. A group with
  nothing under it cannot be saved.
- Removing a parent keeps its items, at the top level where they were.
- The footer stays flat.

**On the site:**
- **Desktop.** A link parent keeps its link, with a small ▾ beside it that opens the sub-menu. A
  group opens by its label.
  - Only one sub-menu is open at a time.
  - Escape, a click elsewhere, or leaving it with Tab closes it.
  - It works without JavaScript too.
  - Near the window's edge it opens the other way.
- **Phones, in Paper.** The sub-items are listed indented inside Menu.
- **Phones, in Plain.** The sub-items open as a panel from the header row.
- While you are on a page from a sub-menu, its parent is marked as the current section.

**When a page goes away:**
- A sub-item whose page is a draft is left out.
- A parent whose page is a draft, but still has live items, shows as a group.
- Deleting a page that is a parent with items turns it into a group with the same label, so its
  items stay. Deleting any other page still removes its menu items.

## The API

Every item in `header` and `footer` now has `children`, an array that is empty for a plain item and
for every footer item.
- A group has `"kind": "group"` and `"href": null`.
- A reader that ignores fields it does not know keeps working until the owner adds a sub-item or a
  group. It then sees only the top level, and `null` for a group's address.
- A reader that refuses unknown fields fails at once, and must be updated for `children`.

Themes: `PublicNavigationItem` gains `children`, and `kind` gains `'group'`.
- The shared `SiteSubmenu`, `SiteNavLink` and `SubmenuScript` components draw sub-menus for the two
  bundled themes.
- [Themes](https://dhanabhon.github.io/tome-cms/extending/themes/) shows how.

## The updater and disk space

The updater will not start an update with less than 5 GB free, so the backup has room.

**What went wrong on 1.9.1.** On the test server the 1.9.1 update stopped at its start and reported
`release_unavailable`, because the disk check runs in that step. The disk had filled with every
application image the updater had replaced, 28 of them.

**Updater 1.4.0:**
- Reports a full disk as `insufficient_disk_space`, and "System" says so plainly, with a link to the
  steps to free space. It sends this code only to an application of 1.10.0 or later.
- After an update succeeds, it removes the older official application images. It keeps the
  installed image and the one before it.
  - It removes only untagged images, which are the ones it pulls itself, and never the PostgreSQL
    or SeaweedFS images.
  - It removes nothing if it cannot read Docker's listing in full.
  - Each removal is logged.

**The application, from 1.10.0, accepts an error code it does not know yet,** and shows it as a
failed update instead of losing the updater's status.

Until the updater is upgraded, free space by hand as
[Troubleshooting](https://dhanabhon.github.io/tome-cms/running/troubleshooting/) explains:
`sudo docker image prune -a --filter "until=24h"`.

## Fixes

- **Concurrent edits.** Saving the menu and deleting a page take the same lock, so a page deleted at
  the moment the menu is saved cannot lose the items under it.
- **Page delete confirmation.** It now says a menu item with sub-items stays as a group.
