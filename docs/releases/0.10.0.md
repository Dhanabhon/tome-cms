# TomeCMS 0.10.0

Date: 2026-09-23
Status: Release candidate; not tagged for production

TomeCMS 0.10.0 is 0.9.0 with the home page's own slides: a picture, a few words and a button
for the top of each language's home page, kept in the admin under their own menu. It also
fetches an article's opening picture first, and fixes two Thai labels that did not fit. This is
still a pre-1.0 clean-install line; the 0.2.0 release gates remain open.

## Upgrading

One migration, `023_home_slides`. Run `npm run db:migrate`, or let the deploy helper run it.
Until it runs, the admin names it at the top of every screen and the home page draws no slides.
An installation created from an earlier version than 0.8.0 still needs what the
[0.8.0 notes](0.8.0.md#upgrading) list.

- A site whose `paper` hero is set to anything but Your slides looks exactly as it did.
- A theme, a plugin or an API client written for 0.9.0 needs no change. `slides` is a new
  property a theme may read, and `/api/v1/content/slides` is a new route.

## Home slides

Home slides sit under Content, after Navigation. Each language keeps its own, the way each keeps
its own menus: a Thai slide and an English slide are two slides.

- A slide is a picture from the library, and if it wants them, a heading, a line under it and a
  button. The button goes home, to one of the site's pages, or to an address, which may open in
  a new tab.
- Up to ten are kept a language and the first five are shown. The rest wait their turn, and the
  list says which ones the site is not showing and why.
- Each slide has its own start and end, or neither. A start at this instant has started and an
  end at this instant has ended, and the list, the site and the API agree on it.
- The owner chooses where the words sit, how much the picture is darkened under them, and which
  of nine points stays in view when a phone crops the picture.
- The list is ordered by dragging or by keyboard, and nothing reaches the site until Save. The
  drawer warns about a picture under 1600 pixels wide, or over 800 KB, before it is saved.
- A picture a slide uses cannot be deleted from the library. The refusal names the slide, and
  the library's own panel lists the slides a picture is kept for.
- A slide with no heading, whose picture has no alternative text, is not shown: a reader using
  a screen reader would meet an unnamed banner. The list says so rather than calling it live.

## The paper theme

`paper`'s hero has a fifth choice, Your slides. One live slide is a still banner, and more are
a slider with its own controls. Three new settings apply to it alone:

- Slides turn by themselves, or wait for the reader. A reader can always stop them, and one who
  asked for less motion never sees them turn.
- Four, six or eight seconds a slide.
- Sliding or fading. Fading needs a browser that animates as it scrolls; any other one slides.

The first slide is fetched first and the others last and lazily, so a slider costs the page no
more than one picture before it looks ready. On a phone, a slide grows to hold its words rather
than clipping them. With no live slide, the hero falls back to text, as covers already did.

## Pictures, fetched in order

- An article that opens with a picture and has no cover asked for that picture lazily, which held
  back the moment the page looked ready. Both themes now fetch it first. A picture further down
  still loads as the reader nears it, and `contentHtml` from the API is unchanged.
- The `plain` theme's cover image is fetched first, as `paper`'s already was.
- The covers slider fetched the pictures a reader had not reached at the same priority as the
  one on screen. They come last now.

## The admin in Thai

- The label over the admin's light and dark switch was too long for the sidebar and broke inside
  a word.
- The site's appearance setting reads the same way as the admin's.

## For theme authors and headless sites

- `ThemeHomeProps.slides` is the live slides of the page's language, in order, at most five. A
  theme that draws no hero, or a hero of its own making, can ignore it. `plain` does.
- `/api/v1/content/slides?locale=` returns the same list, with `Last-Modified` that moves when a
  slide starts or ends as well as when one is saved. The OpenAPI document describes it.
- The public list is read through a five-second, process-local cache, like navigation's, and it
  never fails a page: a broken read draws the hero without slides.

## Validation boundary

- 489 unit tests, `astro check` with no error and no warning, and the production build.
- Integration tests for the table's checks, the whole-list save and its locks, and the library's
  refusal, each against a real PostgreSQL. One of them caught a check that passed on `NULL`.
- The browser suite, run whole, with the phone project's Chromium-only tests skipped as by
  design. The home slides test makes slides in the admin, orders them by keyboard, and checks
  them on one language's home page alone, and at phone width.
- `npm audit --omit=dev` reports no advisory at all.
- Each guard added along the way was checked by putting back the bug it guards against.

What is required before a production tag is unchanged from the
[0.3.0 notes](0.3.0.md#still-required-before-a-production-tag).
