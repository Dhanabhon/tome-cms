# TomeCMS 1.8.1

Date: 2026-10-02
Status: Stable release; tagged and published as a GitHub release

TomeCMS 1.8.1 makes undoing an AI app's changes ask first, under a name that cannot be taken for going
back a page. `/api/v1` and the MCP tools are unchanged.

## Upgrading

- **A managed install** updates from "System" in the admin, as
  [Updating](https://dhanabhon.github.io/tome-cms/running/updating/) describes. There is no
  migration and no new setting, so the updater backs up the database alone.
- **A build from source** upgrades in place by running the deploy helper again.

`deploy/cloud-init.yaml` now installs 1.8.1.

## Undoing an AI app's changes

When an AI app has changed a draft, the editor opens with a bar that names the app and the time, and
one button to put the draft back as it was before the app began. That undo is all or nothing: it
takes back every change the app made, it cannot be redone, and the draft's earlier copy is gone once
it is used.

The button read "Put back", "ย้อนกลับ" in Thai, which reads as going back a page. It asked first only
when the owner had edited the draft since, so in the usual case one press threw the app's work away.
On a real site an owner pressed it twice by mistake, and two rounds of the app's corrections were lost.

- The button now reads "Undo the AI's changes" ("ย้อนสิ่งที่ AI แก้").
- It always asks first. The question says that everything the app changed goes and cannot be brought
  back, and, when the owner has edited since, that their own edits go too.
- Cancel leaves the draft and the bar as they were.

## Testing

- Browser: the button asks before it acts; Cancel keeps the app's version and the bar; confirming
  puts the earlier version back and the bar goes.
- Unit: both languages carry the new words, with no entry missing or left untranslated.
