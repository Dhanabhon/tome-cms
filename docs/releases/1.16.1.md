# TomeCMS 1.16.1

Date: 2026-10-05
Status: Stable release; tagged and published as a GitHub release

TomeCMS 1.16.1 tells search engines who writes a post and whose site it is, and stops pictures from
showing their file names. `/api/v1` keeps its shape.

## Upgrading

- **A managed install** updates from "System" in the admin, as
  [Updating](https://dhanabhon.github.io/tome-cms/running/updating/) describes, or with
  `sudo tome update` on the server. There is no migration, so the updater backs up the database
  alone.
- **A build from source** upgrades in place by running the deploy helper again.
- **The updater** stays at 1.6.0. Nothing to upgrade on the server.

`deploy/cloud-init.yaml` now installs 1.16.1.

## Added

An article's structured data (JSON-LD) now gives search engines two more facts:
- **The author.** It names the author's profiles as `sameAs`, from the links set under Profile in
  the admin.
- **The site.** It names the site's logo, from the brand settings.

Anything in it that looks like markup is escaped, so it cannot leave its `<script>` tag.

## Fixed

**Pictures without alt text.**
- A picture with no alt text is decoration (`alt=""`). It no longer shows its file name instead.
- A picture that was saved with its file name as its alt text is described by what the media
  library says now. If the library has nothing, it is decoration.

**File names as titles.**
- A picture no longer carries its file name as a `title`, which browsers showed as a tooltip.
- This holds on the site and in the content API, for posts and pages saved before this release too.
- Alt text that happens to contain the word `title=` is left whole.

**One gap remains.** The admin's draft preview still shows a stored file-name alt on an old picture.
Only the owner sees that page, and it is never cached or indexed. The editor's own document in the
API (`contentJson`) keeps a picture's title as the editor stored it.

## For theme authors

- **Nothing changed in the theme contract.**
- **Body HTML.** A post's or page's body HTML no longer has `title` on its pictures. A theme that
  read it for a caption should use the alt text or a figure caption instead.

## Testing

- **Unit:**
  - the structured data: the logo, `sameAs`, and the escape;
  - picture alt text and titles, including alt text that ends in a word like "dog" before `title=`;
  - the layout and the post route passing the structured data.
- **Integration:** the content API strips old picture titles from posts and pages.
- **The full suite:** unit, integration, and browser tests on desktop and mobile.
