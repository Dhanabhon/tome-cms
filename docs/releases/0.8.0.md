# TomeCMS 0.8.0

Date: 2026-09-22
Status: Release candidate; not tagged for production

TomeCMS 0.8.0 is 0.7.0 with documents in the library and in articles, menu links that can open
a new tab, a backup that no longer stops at a document or an SVG logo, and uploads that say why
they failed in the owner's language. This is still a pre-1.0 clean-install line; the 0.2.0
release gates remain open.

## Upgrading

Two migrations landed after 0.7.0, and an installation created from it or from 0.6.0 must run
them before starting:

```sh
npm run db:migrate
```

`021_media_documents` · `022_navigation_new_tab`

An installation created from 0.5.0 or 0.4.0 needs what the [0.6.0 notes](0.6.0.md#upgrading)
list as well, one from 0.3.0 what the [0.4.0 notes](0.4.0.md#upgrading) list too, and one from
before that the [0.3.0 notes](0.3.0.md#upgrading). The admin names any migration it finds
unapplied in a banner at the top of every screen.

- `021_media_documents` lets the library hold documents: no dimensions, no alternative text,
  and up to 25 MB where an image may be 8. Its `down` is refused while the library holds a
  document, since dropping those rows would leave cards in articles pointing at nothing.
- `022_navigation_new_tab` gives each menu item a `new_tab` column, which only an item with a
  custom URL may set. Every item there before stays in place. Its `down` drops the column.
- An external S3 store whose CORS rule lists headers must allow `content-disposition` for the
  site's origin before upgrading, beside `content-type` and `x-amz-checksum-sha256`, or
  document uploads fail at the preflight while images keep working. The bundled SeaweedFS
  needs nothing.
- A 0.7.0 site with an SVG logo could not be backed up: `npm run backup` refused its own
  manifest, and a managed update runs a backup first. This release's backup takes it, and
  documents, and objects up to 25 MB.
- Posts and pages keep the HTML they were saved with. Their images gain `loading="lazy"` and
  `decoding="async"` when each is next saved.
- A file in the library is public at its address, `/media/<id>`, whether an article uses it
  or not, as images already were. Something private does not belong in the library.

## For theme authors and headless sites

Nothing a 0.7.0 theme, plugin or API client relied on was taken away. What an article's HTML
can hold grew, and every navigation item gained a field.

- `contentHtml` can hold a file card. A PDF's reads
  `<p class="file-card"><a href="/media/<id>" type="application/pdf" target="_blank" rel="noopener noreferrer"><span class="file-card__name">guide.pdf</span> <span class="file-card__meta">PDF · 1.2 MB</span></a></p>`,
  and any other document's link has no `target`. Without a stylesheet it is a paragraph with a
  link; the core's stylesheet draws it as a card in both themes.
- `contentJson` can hold an `attachment` node with `href`, `mediaId`, `mimeType`, `name` and
  `size`. A client that switches on node types has to draw it or skip it. The OpenAPI document
  does not describe node types, so it does not change for this.
- `/media/<id>` can now redirect to a document: a PDF opens in the browser, and anything else
  downloads under its own name. The public `media` list stays images only.
- An article's images carry `decoding="async"` and `loading="lazy"`, and no other value of
  either.
- A headless site that sanitizes `contentHtml` again has to allow the card's classes
  (`file-card`, `file-card__name` and `file-card__meta`), `type` on a link, and those two image
  attributes, or it loses them.
- Every navigation item carries `newTab`, in `/api/v1/content/navigation`, in its OpenAPI
  schema, and in the `PublicNavigationItem` a theme is given. Only a custom link can have it.
  `paper` and `plain` add `target="_blank"`, `rel="noopener noreferrer"` and, for a screen
  reader, "(opens in a new tab)" in the reader's language.

## Highlights

### Documents in the library

- The library keeps PDF, Word (`.docx`), Excel (`.xlsx`), PowerPoint (`.pptx`), CSV, text and
  ZIP files beside its images, up to 25 MB each.
- Each is judged by its bytes as it streams past, not by its name alone. A file must be what
  its name says; a legacy or macro-enabled Office format is refused, and so is a current one
  carrying macros; a CSV or a text file must be UTF-8, and the admin says how to save one that
  way from Excel.
- Each is stored with the way it is handed out, signed into its upload so the store refuses an
  upload that changes it: downloaded under its own name, or opened in the browser if it is a
  PDF.
- The library filters by type: All, Images, PDF, Documents, Spreadsheets, Slides and ZIP. The
  address keeps the type and the folder, so a reload opens the same view.
- A file the chosen type would hide switches the view to All when it is uploaded, where it is.
  Before, it seemed not to have landed, and the natural next move was to upload it again.
- An upload is given the time its size needs: two minutes, or 50 KB a second when that is
  longer, and three minutes more to be finished.

### Files in articles

- A file goes into a post or a page from + or `/`: chosen from the library, or uploaded there
  and then. It shows as a card with its name, type and size, in the editor as a reader sees it.
- A reader downloads it under its own name, and a PDF opens in a new tab.
- A card cut, copied or pasted stays a card, and says only what the library says of its file.
- A file an article or a page uses cannot be deleted from the library. The refusal names where
  it is used.

### Menus

- A menu item with a custom URL can open in a new tab: the add dialog asks, and each such item
  in the list keeps the box, so it can change without being removed and added again. Home and
  the site's own pages always open in place.

### Uploads that say why

- A failed upload says why in the admin's language: the store refused it, could not be
  reached, or timed out, as well as each of the server's refusals.
- An image dropped or pasted into the editor says so too. Its alert was English throughout,
  title included, and it now checks the file the way the library does.

### Backups

- A backup keeps documents, SVG logos and objects up to 25 MB. Its manifest refused all three
  before.
- `npm run restore:check` puts back how each document is handed out, which the backup does not
  carry, from its row in `media_items`, and checks it. A restore done by hand has to set the
  same header.

### The editor and the site

- An article's images load as they near the window and decode off the main thread. The
  sanitizer gave them both attributes and then removed them again.
- The + menu opens under its button. It opened a fixed 42 pixels below the line, which was the
  button's height and a gap until the button grew to 44.
- The TypeSafe plugin is called Jev (TypeSafe AI). Its id is still `typesafe`, so its switch
  and its sealed API key carry over.

### Documentation

- The README opens with the logo and a list of what TomeCMS does, and shows its architecture
  in the reader's light or dark theme.
- [`CHANGELOG.md`](../../CHANGELOG.md) sums up every version in one place.
- The system overview has an English edition beside the Thai one, and both name Jev (TypeSafe
  AI).

## Validation boundary

The same gates as 0.7.0, green on the commits this release contains: 480 unit tests, 46
integration tests in 26 files, 45 browser tests with the 37 that need Chromium skipped on the
phone project by design, and the build.

Documents were tested against the real SeaweedFS as well as a mocked store: a document keeps
the header signed into its upload, an upload that changes the header is refused, a file
refused for carrying macros leaves nothing in the bucket, and a restore puts a document's
header back. Each guard was checked by putting back the bug it guards against.

The production dependency audit has no new advisory. The moderate ones are all still the one
in `@tiptap/core` (GHSA-cp6q-959q-f8rh), and the fix for it is in the 2.27.3 this release
pins: it was backported there, while the advisory names only 3.30.4 as patched, so audits
report every 2.x release. `mergeAttributes` in the installed 2.27.3 defines `__proto__` as a
plain property rather than merging it. TomeCMS would not be exposed either way: the editor's
schema drops an own `__proto__` key before anything is stored, so the admin never loads one
back, and a test pins that.

A backup manifest for the largest library the format allows, 100,000 documents of 25 MB each,
comes to 33.3 MB against the updater's limit of 32 MiB, with 0.8% to spare. No field should be
added to a manifest's objects without raising that limit first.

The updater's timeout test named in the [0.6.0 notes](0.6.0.md#validation-boundary) is still
to be fixed. The release workflow can still be exercised only by tagging a release. What is
required before a production tag is unchanged from the
[0.3.0 notes](0.3.0.md#still-required-before-a-production-tag).
