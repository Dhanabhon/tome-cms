# TomeCMS 0.7.0

Date: 2026-09-22
Status: Release candidate; not tagged for production

TomeCMS 0.7.0 is 0.6.0 with tables and alignment in the editor, links that open a new tab
only when their writer asks, a theme choice that floats from one button, and an editor its
owner can always leave. This is still a pre-1.0 clean-install line; the 0.2.0 release gates
remain open.

## Upgrading

Nothing to migrate: no migration landed after 0.6.0, so an installation created from that
candidate starts as it is. One created from 0.5.0 or 0.4.0 needs what the
[0.6.0 notes](0.6.0.md#upgrading) list, one from 0.3.0 what the
[0.4.0 notes](0.4.0.md#upgrading) list as well, and one from before that the
[0.3.0 notes](0.3.0.md#upgrading).

Posts and pages keep the HTML they were saved with, and the links in them keep opening a new
tab, as every link did before.

## For theme authors and headless sites

Nothing a 0.6.0 theme, plugin or API client relied on was taken away. What an article's HTML
can hold grew, and the theme toggle's markup changed.

- `contentHtml` can hold a table: `<div class="tableWrapper"><table><tbody>`, rows of `<th>`
  and `<td>` cells that each hold paragraphs, and `colspan` and `rowspan` where cells were
  merged. The header row is the first `<tr>` of the `<tbody>`, not a `<thead>`, so a theme
  styles `th`, or `tr:has(> th)`, rather than `thead`. A `div` keeps its class only as that
  wrapper.
- The core's stylesheet makes the wrapper scroll sideways, so a wide table never widens the
  page. The table itself is the theme's to draw; `paper` and `plain` rule its rows, the header
  row more strongly.
- A paragraph or a heading can carry `style="text-align:center"` or
  `style="text-align:right"`, and no other style. Left is the absence of one. A table cell is
  aligned through the paragraphs in it.
- A link has `target="_blank"` only when its writer asked for a new tab. Every link keeps
  `rel="noopener noreferrer"`.
- `contentJson` can hold `table`, `tableRow`, `tableHeader` and `tableCell` nodes, a
  `textAlign` attribute on `paragraph` and `heading`, and a link mark whose `target` is null.
  A client that draws `contentJson` itself meets them there.
- A headless site that sanitizes `contentHtml` again has to allow the table tags, the
  wrapper's class, `colspan`, `rowspan` and that one `text-align` declaration, or it loses
  them.
- `<ThemeToggle>` takes the same props and draws differently. `.ui-theme` is now a `div`
  holding a `button.ui-theme__trigger` and a `fieldset.ui-theme__panel` popover, and
  `.ui-theme__track` is gone; the options keep their classes. `name` now also names the panel
  and the anchor that tethers it, so it still has to be unique on the page. A theme that
  styled the old row has to follow it.
- `--shadow-float` is the one shadow in the token set, with a light and a dark value, for what
  floats over the page. The theme panel and the language menu wear it.

## Highlights

### Tables

- A table goes in from the + menu or `/`, three by three with a header row, and Tab walks its
  cells. With the cursor in a cell, a bar over the table's corner adds a row or a column and
  deletes a row, a column or the table. `/` offers the same five, because Tab inside a table
  moves between cells and a keyboard cannot reach the bar.
- The two bars take turns. Words chosen in a cell bring the formatting bar; a cursor, or cells
  chosen together, bring the table's. Neither menu offers a table inside a cell.
- A table cannot be resized, and one wider than a phone scrolls inside its own box. A table
  pasted from a spreadsheet keeps its merged cells, and loses the inline widths and the
  column group Tiptap adds.
- Each cell's words stand apart in the text a post is read, counted and judged by, so the
  last word of one cell never runs into the first of the next.
- The typography styles' table borders now come from the rule tokens, so the editor's tables
  follow the dark theme.

### Alignment

- The formatting bar and the table's bar align a line left, centre or right. Left is no
  alignment at all, so choosing it clears whatever was set.
- There is no justify. Thai puts no spaces between its words, so a justified Thai line has
  only its letters to stretch.
- An alignment reaches the reader. The server's HTML is now made by a few lines of TomeCMS's
  own instead of `@tiptap/html`, whose `generateHTML` dropped every style: an alignment showed
  in the editor and was never stored. `zeed-dom`, which `@tiptap/html` used, is a dependency
  of its own, at the same version.

### Links

- The link button is a chain from the admin's own icon set. It was an arrow, which reads as
  "go" and never as "link".
- The link dialog asks whether the link opens a new tab, with the box ticked to begin with.
  Before, every link opened one, because Tiptap gives each one `target="_blank"` unless told
  otherwise and nothing told it.

### The theme choice

- The row of three, System, Light and Dark, is one round button that shows the choice in
  force, and a panel that floats from it. The panel is still a group of native radios: the
  arrow keys walk it, a click outside or Escape puts it away, and focus goes back to the
  button. A choice made with a pointer applies and closes the panel; one made with the arrow
  keys applies and leaves it open for the next.
- The panel is tethered with CSS anchor positioning where the browser has it, under the
  button or, at the foot of the admin sidebar, over it. Where the browser does not, a few
  lines of script place it the same way. A browser without popovers draws the row of three
  it always did, with no polyfill.
- It opens from the button's corner and closes quicker, and the button's icon turns from the
  old choice to the new. For a reader who asked for less motion, both only fade.
- In `paper`, the controls stand together at the end of the header, the language menu first
  and the theme button last. Without a navigation to push them there, the button used to sit
  alone in the middle of the row.

### The editor

- The formatting bar is never cut off. A word chosen at the start of a line put the bar past
  the canvas's left edge, where the canvas clipped it: the first button half gone, or all of
  the bar over a short word.
- A draft that cannot be saved no longer keeps its owner in. Back saves before it leaves, and
  a draft with no title cannot be saved, so Back, Manage categories and a page's Back showed
  the same error and went nowhere. When that save fails now, leaving asks: Leave without
  saving, or Stay in editor. A new draft with nothing written in it is left with no save and
  no question.
- The + menu opens where all of it can be chosen. With one more item, at a laptop's height, it
  opened above the line and under the editor's bar, as it already did on a phone. Its room now
  ends at the bar. When it fits on neither side, it opens on the side with more room and
  scrolls inside it.

### Documentation

- The README is in two parts: running a site, for whoever installs one and keeps it going,
  and developing TomeCMS, for whoever works on the code.
- It says what server a site needs, from measuring this release's code on an empty site: at
  least 1 vCPU, 2 GB of memory with 2 GB of swap and 25 GB of SSD, and 2 vCPU, 4 GB and 50 GB
  recommended. It says where the disk goes, backups included, and which ports the reverse
  proxy forwards to.
- It said the core declares two plugin hooks, both for the sign-in. It declares three; the
  public page and writing suggestions are the other two.

## Validation boundary

The same gates as 0.6.0, green on the commits this release contains, with no warnings left on
the CI run. A table is tested from the editor to the published page, where it scrolls inside
its box on a phone; the theme panel in a browser with anchor positioning, in one without it,
and on a phone; and the stored HTML for what the sanitizer keeps and what it drops.

Each guard was checked by putting back the bug it guards against, and three of the new checks
were found not to be checks before the code they cover was committed: one kept the header's
controls together by the gap between them, which a swap passed; one found the theme panel
visible while it was still fading out; and one looked for the formatting bar before its
quarter-second wait was over, so a bar that should not have come had not come yet.

The production dependency audit has no new advisory. The moderate ones are all still the one
in `@tiptap/core` (GHSA-cp6q-959q-f8rh), which the table and alignment extensions depend on as
well, and it still waits on the editor's own dependency.

The updater's timeout test named in the [0.6.0 notes](0.6.0.md#validation-boundary) is still
to be fixed. The release workflow can still be exercised only by tagging a release. What is
required before a production tag is unchanged from the
[0.3.0 notes](0.3.0.md#still-required-before-a-production-tag).
