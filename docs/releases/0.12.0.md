# TomeCMS 0.12.0

Date: 2026-09-26
Status: Release candidate; not tagged for production

TomeCMS 0.12.0 is 0.11.0 plus five things:

- a YouTube or Vimeo video in an article or page
- Stats that writes nothing to a reader's browser
- a Stats screen that shows the report at zero before anyone is counted
- drawers, dialogs and menus that arrive and leave with motion
- documentation at [dhanabhon.github.io/tome-cms](https://dhanabhon.github.io/tome-cms/), in English and Thai

0.11.0 began a feature freeze before 1.0.0. This release is the one exception to it, and the
freeze starts again here: only fixes from now until 1.0.0. This is still a pre-1.0 release
candidate. A 0.x site upgrades in place when the deploy helper is run again from a newer
checkout.

## Upgrading

There is no migration and no new runtime dependency.

To fetch a clip's title and poster, the server must reach `www.youtube.com`, `vimeo.com`,
`i.ytimg.com` and `i.vimeocdn.com` over https. Without that, a video still goes in, with no
poster, and readers can still play it.

TomeCMS sets no Content Security Policy. If you set one at your proxy, it must allow
`frame-src https://www.youtube-nocookie.com https://player.vimeo.com`, or the player cannot load.

An installation created from a version earlier than 0.11.0 still needs what the
[0.11.0 notes](0.11.0.md#upgrading) list.

## Videos

A writer can put a YouTube or Vimeo clip in a post or page, and a reader can play it on the site.

- A link pasted alone on an empty line becomes a video. Pasted into a sentence, or on an empty
  line inside a table, a list or a quote, it stays a link. The writer can also choose Video in
  the `+` or `/` menu, outside a table, and paste the link there.
- TomeCMS reads the usual links to one clip: `youtube.com/watch?v=`, `youtu.be/`, Shorts,
  YouTube's embed links, `vimeo.com/<number>`, Vimeo channel links and `player.vimeo.com`, with
  a start time from `t=`, `start=` or `#t=`. A playlist with no clip in it, and a host that only
  looks like YouTube or Vimeo, are refused.
- The card goes into the article at once. The server then asks YouTube's or Vimeo's oEmbed
  address for the clip's title and poster, fetches the poster once, and keeps it in the file
  library under the clip's title. It reaches only those four hosts, over https, follows no
  redirect, gives up after 5 seconds and reads at most 2 MB. An owner can look up 30 clips a
  minute.
- When the clip is private, or YouTube or Vimeo does not answer in time, the video stays in
  without a poster, and the editor says why in the admin's language. The writer can still
  publish it.
- The library treats a poster as in use, as it does a picture in the text, and will not delete
  it while an article holds it.

A reader sees the poster with a play mark, and a caption with the clip's title and YouTube or
Vimeo. Nothing on the page talks to YouTube or Vimeo until the reader presses play: the poster
is the site's own file, and the video is only a link. Pressing play puts the player in the
poster's place, from YouTube's no-cookie host, `www.youtube-nocookie.com`, or from Vimeo in its
do-not-track mode, `player.vimeo.com` with `dnt=1`, and moves focus into it. The site sets no
cookie and writes nothing to the browser for a video, so with the defaults the public site still
needs no consent banner. The small script that plays a video loads only on a page whose content
has one, and labels each poster "Play video" with the clip's title in the page's language.

Without JavaScript, the poster is a link that opens the clip on YouTube or Vimeo. The Image
lightbox plugin leaves a poster alone, so pressing it plays the clip. The stored HTML never
holds an `iframe` or a `script`: the player exists only in a reader's browser, after a click.

These are left out:

- other providers, such as Facebook and TikTok, whose embeds load their own tracking scripts
- a video file of the site's own
- a portrait frame for Shorts, which play in the same 16:9 frame as any clip
- a caption the writer writes; the clip's title and provider are the caption
- choosing another poster from the library

## Stats writes nothing to a reader's browser

Counting readers for Stats no longer writes anything to a reader's browser, so it needs no
consent banner. In 0.11.0 the counting script kept a mark in `sessionStorage` to tell a reload
or a step Back from a new view. It now reads the browser's own record of how the page was
opened: a reload, or a step Back or Forward, still sends nothing. Two counts change as a result.
Following a link back to a page already open in the tab now counts as a second view, and reading
an article again after reloading it counts as a second read.

## Stats before the first reader

A site that has counted nobody yet used to show one empty box in place of the Stats report. It
now shows the report at zero, under a notice headed "Nobody counted yet". The notice says that
numbers appear once someone opens a published post or page, that the browser used for the admin
is not counted and neither is a reader who turned on Do Not Track or Global Privacy Control, and
that opening the site on a phone or in another browser shows a first number. Until there is a
view, the read ratio shows a dash, and the chart's table and each list say "Nothing was viewed
in this period." instead of rows of zeros.

## Drawers, dialogs and menus

Drawers, dialogs, menus and popovers, in the admin and on the site, now arrive and leave with
the same motion. Drawers slide to and from their edge, dialogs rise with a small scale, and menus
drop in. Each plays its exit before it closes, whether it is closed with Escape, a button or a
click outside it, and a Save in a plugin's drawer plays it too. Anyone who asked their system
for less motion gets a short fade with nothing moving. Only `transform` and `opacity` move.

## Documentation

TomeCMS has a documentation site at
[dhanabhon.github.io/tome-cms](https://dhanabhon.github.io/tome-cms/), in English and Thai. It
covers installing and running a site, every screen of the admin with its picture, each plugin,
the headless API with a reference generated from the app's own OpenAPI document, extending
TomeCMS, and contributing. The site is built with Astro Starlight from `website/`, which has
its own dependencies apart from the app's. The README is now an introduction that links there.

The site's pages on writing, privacy, the headless API and the Image lightbox describe the video
as this release builds it.

## For theme authors, plugin authors and headless sites

- A document can hold a `video` node with five attributes: `provider` (`youtube` or `vimeo`),
  `videoId` (11 characters of `A-Z`, `a-z`, `0-9`, `_` or `-` on YouTube, digits on Vimeo),
  `start` (whole seconds, or `null`), `title` (at most 200 characters, or empty) and `mediaId`
  (the poster in the library, or `null`). The node holds no address; build one from `provider`
  and `videoId`. The save refuses a node with any other attribute, or with a poster that is not
  a ready picture in the site's library.
- `contentJson` has no schema for its nodes in the OpenAPI document, so this is where the video
  node's shape is described. The documentation's API overview describes it too.
- `contentHtml` renders the node as `figure.tome-video`. Inside it, `a.tome-video__play` links
  to the clip on YouTube or Vimeo and holds the poster and a `span.tome-video__title` for screen
  readers, and a `figcaption` names the clip and its provider. Stored HTML carries no class
  but these three, the file card's and the table wrapper's.
- The poster is in the item's `media`, with its address and size, as a picture in the text is.
- Every theme gets the `.tome-video` styles from `global.css`: a 16:9 box with the play mark on
  the poster, the title hidden from sight, and the shared focus ring. A theme needs no change.

## Validation boundary

- `npm run check`: `astro check` with no error and no warning, and the scripts' self-tests.
- `npm run test:unit`: 555 tests, all passing. They cover every link form the parser takes and
  the ones it refuses, the save check, the content filter keeping `figure.tome-video` and still
  dropping `iframe`, and the lookup with `fetch` replaced: other hosts, redirects, the 2 MB
  limit, the deadline and a private clip.
- `npm run test:integration`: 59 tests in 39 runs against a real PostgreSQL and object store,
  all passing. A saved article with a video lists its poster in the API's `media`, and the
  library will not delete a poster in use.
- `npm run test:e2e`: 136 tests on the desktop and phone projects, 93 passing and 43 skipped
  (the specs that run on the desktop project only), none failing. The editor spec pastes a link
  on an empty line and in a table cell, and adds a video from a menu. The video spec checks that
  a published page makes no request to YouTube, Vimeo, `ytimg` or `vimeocdn` before a click, that
  the player is the no-cookie or `dnt=1` one with focus in it, that the browser holds no cookie
  and no storage afterwards, that the link works with JavaScript off, and that the lightbox
  leaves a poster alone. The admin lookup is answered in the browser,
  so no test reaches YouTube or Vimeo. The alignment test in `editor-blocks.spec.ts`, a known
  flake on `main`, passed in this run.
- The documentation site: `npm --prefix website run check` found every page's twin and no
  listed mark, and `npm --prefix website run build` built 95 pages with every internal link
  valid.
