# TomeCMS 1.14.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the design release.
- The owner's group-D rulings: Paper on cream with hairlines and Google Sans only; Almanac's tone
  band for coverless cards; Plain in Google Sans.
- Every group-C quality fix from the hallmark audit, across the three themes and the admin.
- Per-theme font preloading.
- A committed theme screenshot instrument.

**Architecture:** CSS and template changes inside each theme's own directory, plus a small set of
shared changes (the theme manifest's `preloadFonts`, the missing page, the language switcher, and
fonts.css). The admin's changes stay inside its existing styles and components. Each area is its own
task, and the screenshot instrument comes first, so a "before" set exists.

**Tech Stack:** Astro 7, React 18 islands, Tailwind 3 (preflight on), CSS custom properties, Playwright
(the e2e and shot instruments), and `node:test`.

**Spec:** `docs/specs/2026-10-04-design-release-1.14.0-design.md`. It is binding, and it cites the
audit findings as "paper #7" and so on.

**Audit reports**, the evidence with file:line: `.worktrees/develop/.superpowers/hallmark-audit/{paper,almanac,plain,admin}.md`. They are git-ignored, so the controller copies them into the release worktree's SDD workspace.

## Global Constraints

- **Git:**
  - never `git stash`;
  - stage by explicit path;
  - commit with `git commit -F <file> -- <paths>` as its own command;
  - no attribution lines;
  - conventional subjects in plain English;
  - never push or merge.
- **Scope:**
  - no migration;
  - no change to `/api/v1`, the updater or `UPDATER_VERSION` (it stays `1.6.0`);
  - no new home layout (D1);
  - no new features.
- **The spec's Common rules apply to every task:**
  - tokens only;
  - hover inside `@media (hover: hover)`;
  - an `:active` state on pressed controls;
  - touch targets of at least 44px under `(pointer: coarse)`;
  - motion on `transform` and `opacity` only, with no overshoot;
  - for Thai: no tracking, no uppercase, leading of at least 1.2, no italic emphasis;
  - no sideways scroll at 320, 375, 768 or 1440;
  - the prose measure set in rem or em.
- **`npm run build` must pass before every commit.** Tailwind scans `src/**/*.ts`, so a regex that
  looks like a class can break the CSS build.
- **`npm run check` must pass before every commit.** That includes `tome check` and the token tests,
  so no raw colours in themes.
- **Every task proves its visual change.** Run the theme-shots or admin-shots instrument with a task
  label, open the changed screens at 375 and 1440, in light and dark, and list the image paths in the
  report.
- **Tests:**
  - **Unit:** `node --import tsx --test tests/unit/<f>.test.ts`.
  - **e2e:** `npm run test:e2e -- tests/e2e/<f>.spec.ts --project=desktop`. Specs that own a database
    are registered in `tests/e2e/own-worker.ts`. A spec file may use at most 5 `/recovery` sign-ins.
  - Use TDD wherever a CSS or DOM assertion can see the change.

## Review Focus

1. **Thai on every changed surface.** A two-line Thai title in Google Sans (Paper, Plain) must not
   collide. A Thai category name in Almanac's tone band must fit or end in an ellipsis. *Pinned in
   Tasks 3, 4 and 5, with Thai fixtures in the shots and a 375-width check.*
2. **Dark mode for every new surface:** Paper's cream to dark and tinted ink, Almanac's band, the
   admin's hover fills. Contrast must hold at 4.5:1 for text. *Pinned in each task, with a
   contrast-pair test where the token tests can express it.*
3. **A theme with no `preloadFonts`,** and a `tome theme new` copy. No crash, no broken preload link,
   and `tome check` passes. *Pinned in Task 2.*
4. **Plain's scrolling category row** works by keyboard: focus moves the scroller to the focused tab.
   *Pinned in Task 5.*
5. **One primary action per admin screen** stays true in every state of each screen: empty, filled,
   and with unsaved changes. *Pinned in Task 6, as an e2e count across those states.*

### Task 1: The theme-shots instrument, and the "before" sets

**Files:**
- Create: `tests/e2e/theme-shots.spec.ts` (and add it to `tests/e2e/own-worker.ts` if it owns a
  database).

**What it does:** follow `tests/e2e/admin-shots.spec.ts`. It skips unless `THEME_SHOTS=<label>` is
set, stands up its own stack, and seeds through the real admin or the services. The seed:
- 10 published posts across 4 categories, in th and en, some with covers and some without;
- one post with h2, h3, both kinds of list, a blockquote, a code block, inline code, an image and an
  attachment;
- a post whose Thai slug is `ขนมปัง-ยามค่ำ`, with a two-line Thai title;
- an empty category;
- one page;
- a header menu with a sub-menu, and footer links;
- Paper's home slides (two, with words).

**Shots:** for each of paper, plain and almanac, at 320, 375, 768 and 1440, in light and dark, full
page:
- home;
- post;
- post-cover;
- page;
- category;
- an empty category;
- search;
- 404.

They go to `.superpowers/theme-shots/<label>/<theme>/<screen>-<width>-<scheme>.png`, with a
`measure.json` holding a few rects: the brand, the first card, the article title, and the first
prose paragraph's width in characters.

- [ ] **Step 1:** write the spec. Run it with `THEME_SHOTS=before`, and run
  `ADMIN_SHOTS=before npm run test:e2e -- tests/e2e/admin-shots.spec.ts --project=desktop`.
- [ ] **Step 2:** open about 10 shots and check they show what they claim to show.
- [ ] **Step 3:** run `npm run check`, `npm run build` and `npm run test:unit`. Commit:
  `test: a screenshot instrument for the three themes`.
