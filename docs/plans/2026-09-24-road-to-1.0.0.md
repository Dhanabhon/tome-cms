# The road to 1.0.0

Date: 2026-09-24
Status: Agreed order of work; each step gets its own spec and plan where it needs one

1.0.0 is an update boundary before it is a feature set: the first managed-VPS installation that
can apply a verified update from the admin, `1.0.0 → 1.0.1` (see [releases/1.0.0.md](../releases/1.0.0.md)).
Its releases must be **public, published and immutable**, because the installer and updater
download the manifest and attestations from GitHub without a credential. The repository is
private today, so it has to open **before** `v1.0.0` is tagged, not after.

| # | Step | What it is | Needs from the owner |
|---|---|---|---|
| 0 | Popup plugin | Six tasks built and reviewed; the final review's fix wave, then merge | the merge |
| 1 | Stats | [spec](../specs/2026-09-24-stats-dashboard-design.md) → plan → build | review of the spec and plan |
| — | **0.11.0** | Maintenance, popup and Stats released as a feature freeze; only fixes after it until 1.0.0 | the release |
| 2 | Before going public | A secret scan of the whole history (every commit, not only the tip); a read of every file under `docs/` that becomes public; `SECURITY.md`, `CONTRIBUTING.md`, issue and pull-request templates; branch protection; Actions permissions for pull requests from forks; the GHCR package's visibility | the scan's results |
| 3 | Go public | Switch the repository's visibility | **the owner does this**; it cannot really be undone |
| 4 | v1.0.0 and v1.0.1 | Tag through `release.yml` with attestations; install `v1.0.0` fresh and update to `v1.0.1`, filling the four acceptance rows in releases/1.0.0.md | **two real HTTPS VPSs**, `linux/amd64` and `linux/arm64` |
| 5 | Documentation on GitHub Pages | A site apart from the app (Astro Starlight, the project's own stack, Thai and English): installing, the admin, themes, plugins, the headless API from the OpenAPI document, backup, restore and update, contributing | the outline; can start once step 3 is done, since Pages on a private repository needs a paid plan |

Step 4 is the one that depends on machines rather than code.
