# Release 1.20.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Responsive image variants with srcset, a public page per category, and four small fixes, with the docs screenshots re-shot.

**Architecture:** Image variants are generated from the buffer the upload already holds, stored as their own objects and rows in `media_variants`, served through `/media/<id>?w=`, and written into public HTML as `srcset`. Categories gain a slug and per-language descriptions; a new `/[locale]/category/[slug]` route renders the theme's filtered home with its own SEO.

## Review Focus

1. A failed variant never fails an upload; variants never outlive their image (delete, cleanup, reset all account for them).
2. Memory: generation is serialised; a 40 MP / 8 MB image does not hold more than one decode at a time.
3. The body-image rewrite must not break existing HTML (alt texts, stripped titles, lead-image logic, links around images) and must be idempotent.
4. Category pages: canonical/hreflang/404 correct; the `?category=` redirect keeps old links working; the default category never gets a page.
5. Additive API change only; existing clients keep working.

### Task 2: Generating, storing and deleting variants
**Files:** `src/server/media/variants.ts` (create), `src/server/media/service.ts` (finalizeUpload, importImage, createMediaFromBytes, deleteMedia), `scripts/media-cleanup.ts`, `scripts/reset-installation.mjs` (knownObjects), tests.
- `makeVariants(buffer, mime, width)` → `{ width, body }[]` per the Global Constraints (`.rotate().resize({ width, withoutEnlargement: true }).webp({ quality: 78 })`, metadata stripped; skip animated: `metadata().pages > 1`).
- A process-wide serial queue so only one image is processed at a time.
- After an image is finalized/imported/created, generate and store variants (objects via PutObject with immutable `CacheControl` and `ContentType: image/webp`, rows in `media_variants`); any failure is logged (media id only, no secrets) and never thrown to the caller.
- `deleteMedia` deletes variant objects (best effort, before the row cascade) — a variant object that fails to delete must not leave the media item undeletable; reset's `knownObjects` includes `media_variants.object_key`; cleanup removes variant objects for `delete_failed` items.
- [ ] Tests: unit (sizes for 400/1000/2000/4000-wide inputs; animated skipped; WebP without EXIF), integration (finalize creates rows+objects; delete removes them; reset counts them; a generation failure leaves the upload ready). Commit `feat: images get smaller copies when they are uploaded`.

### Task 3: Backfill and the `?w=` address
**Files:** `src/server/media/variants.ts`, `src/pages/health/ready.ts` (the readiness one-shot pattern from 1.16.4), `src/pages/media/[id].ts`, tests.
